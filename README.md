# Fashion Studio

React/Vite 의류 상세페이지 편집기. 화면은 **자동 제작** 하나만 있습니다(예전 1차 사진 보정·AI 착용샷·2차 상세페이지 탭과 FASHN·Anthropic·Gemini 등 `VITE_` 키를 쓰던 코드는 삭제했습니다).

## 실행

Node 24에서 검증했습니다. 현재 저장소에는 lockfile이 없습니다.

```sh
npm install --package-lock=false
npm run dev
```

- `npm run build` 후 `npm start`: 빌드된 앱과 AI API를 함께 실행합니다. 기본 주소는 127.0.0.1:3000입니다.
- `npm test`: 실제 API 비용 없이 서버와 상세페이지 문서 구성을 검사합니다.
- `vite preview`만으로는 AI API가 실행되지 않습니다.

서버 환경에 기존 `OPENAI_API_KEY`를 연결합니다. **VITE_ 접두사를 사용하지 않습니다.** 개발 서버는 `.env.local`도 지원하며 프로덕션 서버는 실행 환경 변수를 사용합니다. 모델 선택 변수는 `OPENAI_IMAGE_MODEL`(기본 `gpt-image-1`), `OPENAI_TEXT_MODEL`(기본 `gpt-4.1-mini`)입니다.

## Photoroom 누끼·보정

사진 누끼·중앙 정렬은 Photoroom Image Editing API(`image-api.photoroom.com/v2/edit`)로 처리합니다. 서버 환경변수 `PHOTOROOM_API_KEY`가 필요합니다(**VITE_ 접두사 금지**). Photoroom 웹 편집기(app.photoroom.com)의 화면 작업과는 별개이며, API 키와 API 요금제가 필요합니다.

- 기본: 배경 누끼 + 중앙 정렬(선택) + 조명 보정(선택, `lighting.mode=ai.preserve-hue-and-saturation`로 색상 유지). 원본 옷은 그대로 둡니다.
- 선택: 기본 프롬프트(마네킹 오염 정리·구김 펴기·좌우 대칭·기울기 바로잡기)와 직접 입력 프롬프트. 구김 펴기는 Photoroom AI Ironing(`ironing.mode`), 나머지는 Edit With AI(`editWithAI.prompt`)를 사용합니다.
- Photoroom은 호출 1번당 $0.10이며 옵션 수와 관계없이 같으므로, 사진 1장당 한 번에 모두 요청합니다. AI 보정이 거절되면 누끼만 다시 요청(추가 1회)해 결과와 경고를 돌려줍니다.
- OpenAI 엔진을 고르면 Photoroom 누끼 후 OpenAI 이미지 편집으로 프롬프트를 적용합니다.
- 생성형 보정(Edit With AI 출력은 1K)이라 질감이 달라질 수 있어 기본값은 꺼져 있습니다.
- 각 사진의 ‘이 사진 보정 설정’에서 사진별로 다른 설정을 쓸 수 있습니다. 선택하지 않으면 위쪽 기본값을 따릅니다.
- 사진마다 원본·보정본을 최대 8개 버전으로 보관하며 ‘이전으로 / 다시 적용’은 저장된 결과만 바꿔 API를 호출하지 않습니다. 같은 사진·같은 설정으로 다시 누르면 저장된 결과를 재사용합니다(새로고침하면 사라짐).
- ‘개별 PNG 저장’은 2MB를 넘으면 픽셀 크기를 단계적으로 줄여 2MB 이하 PNG로 저장합니다. 작은 사진은 원래 크기 그대로 저장합니다.
- 화면 상단에 Photoroom 남은 이미지 수를 표시합니다(`GET /v2/account`, 과금 없음).
- 화질: 업로드 사진은 긴 변 최대 2400px(JPG, 서버 요청 한도 4.2M자 이내)로 보내고, 배경 제거에 `pr-hd-background-removal: auto`(HD 배경 제거)를 씁니다. 공통 밝기 기본값은 0%입니다.
- 의류 전용 옵션: AI 그림자(`shadow.mode=ai.auto-with-overrides`, `pr-ai-shadows-model-version: 2026-04-15`, 기본 꺼짐), 마네킹 처리(그대로 / 고스트 마네킹 `ghostMannequin.mode` / 플랫레이 `flatLay.mode`). 고스트·플랫레이는 단독 요청이며 1K 출력입니다.
- Edit With AI·고스트 마네킹·플랫레이는 결과가 1K로 작아지며 화면에 경고를 표시합니다. AI 다림질은 2K까지 유지합니다.
- 실제 사진 테스트(1500×2000 마네킹 사진): HD 누끼·AI 다림질은 원본 해상도 유지, 고스트 마네킹은 896×1200이며 없던 목 라벨이 생김, AI 그림자는 서 있는 마네킹 사진에서 왼쪽 아래에 어색한 그림자.
- 색감 통일(API 비용 없음, `src/utils/colorMatch.js`): 보정 컷에서 ‘🎨 이 컷 색감을 기준으로’를 누르면 그 컷 옷의 대표 색(Lab에서 가장 넓은 색 영역, 밝은 무채색 마네킹은 제외)을 기준으로 저장합니다. ‘기준 색감으로 맞추기’는 다른 컷의 대표 색이 기준과 같아지도록 컷 전체의 L·a·b를 같은 양만큼 옮깁니다(강도 슬라이더, 한 번에 L ±14·a/b ±12 제한, 하이라이트·그림자 보호). 결과는 새 버전으로 저장되어 ‘이전으로’로 되돌릴 수 있고, ‘앞으로 보정하는 컷도 자동으로 맞추기’를 켜면 새 보정 결과에 바로 적용합니다. 색감 기준이 있으면 대표 사진 밝기 자동 맞춤은 끕니다.
- 기본 프롬프트 문장은 `src/utils/retouchPresets.js`에서 수정합니다.
- 상품 문구 자동 작성은 계속 `OPENAI_API_KEY`를 사용합니다. 없으면 문구 작성만 건너뜁니다.
- 실제 Photoroom API로 누끼 단독 호출과 누끼+AI 다림질+Edit With AI+조명 결합 호출이 HTTP 200·투명 WebP를 반환하는 것을 테스트 이미지로 확인했습니다. 서버 테스트는 모의 응답으로 요청 형식을 검사합니다.

## 여러 상품 저장

상단 ‘상품 선택’에서 상품을 여러 개 만들고 전환합니다. 사진·문구·사이즈·보정 설정·쇼피 정보는 이 브라우저의 IndexedDB에 자동 저장됩니다(서버로 보내지 않음, 다른 컴퓨터·브라우저에서는 보이지 않음). 보정 결과 재사용 캐시는 저장하지 않습니다.

## 쇼피 등록 준비 (05)

- 영문 상품명·설명 자동 작성: `/api/studio?action=shopee` (OpenAI). 입력에 없는 소재·원산지·세탁법·치수는 쓰지 않도록 지시합니다.
- ‘쇼피 등록 묶음 다운로드 (ZIP)’: 사진을 흰 배경 정사각형 JPG(800~1600px, 2MB 이하)로 바꾸고 대표 → 모델컷 → 디테일 → 영문 사이즈표 순서로 최대 9장 담습니다. `listing.txt`(상품명·설명·사이즈표·사진 순서)와 `listing.json`이 함께 들어갑니다. 파일 이름은 영문입니다.
- 사진 기준(1:1, 800px 이상, 2MB 이하, 최대 9장)은 판매자 가이드 기준값이며 `src/utils/shopeeExport.js`의 `SHOPEE_IMAGE`에서 바꿉니다.
- 쇼피 Open Platform 승인 후 ‘쇼피에 바로 등록’(KRSC Global Product API)을 추가할 예정입니다.

## 편집 흐름

1. 옷 종류와 확인된 상품 정보를 입력하고 대표 정면 사진을 선택합니다.
2. `사진 일괄 누끼·보정 및 문구 제작`으로 배경 제거, 제한적인 주름·조명 정리와 문구 작성을 실행합니다. 디테일컷은 자동으로 만들지 않습니다.
3. 모델컷은 `모델컷 적용`을 선택하고 실제 사진을 넣었을 때만 출력합니다. 옆면·후면·특정 디테일도 실제 사진이 있는 경우만 사용하며, 없는 시점을 생성하지 않습니다.
4. 각 자리에서 JPG/PNG/WebP 파일을 선택하거나 이미지 영역을 클릭하고 Ctrl+V로 클립보드 이미지를 붙여넣을 수 있습니다. 사진당 업로드 제한은 20MB이며, 브라우저에서 긴 변 1600px로 축소합니다. 업로드한 원본은 `보정 전`으로 표시되며 개별 누끼·보정 또는 일괄 처리가 필요합니다. 이미 편집된 외부 사진은 그대로 배치·출력할 수도 있습니다.
5. 정면 확대·상단·하단·원단컷 등 디테일컷은 각 자리에 사진을 직접 넣고 ‘이 사진 누끼·보정’으로 개별 보정합니다. 사진이 없는 자리와 포함 체크를 해제한 컷은 출력에서 빠집니다.
6. 긴팔티셔츠·반팔티셔츠·조끼·원피스·긴바지·반바지에 따라 치수 실루엣과 입력 칸이 바뀝니다. 의류 종류별 입력은 따로 유지합니다. 상의에는 사이즈·가슴단면·총장, 하의에는 사이즈·허리단면·밑위·엉덩이 단면·허벅지 단면·밑단단면·총장이 표시됩니다. 값은 추정하지 않고 빈칸은 `—`로 출력합니다.
7. 제목·설명·사진 제목·섹션 제목·모델 설명·치수 안내를 수정하고 전체 미리보기, 전체 PNG 또는 HTML을 저장합니다. 개별 사진도 PNG로 저장합니다.

최종 순서는 **대표 정면샷 → 상품 문구 → Fit guide(선택) → Detail → Size**입니다. 모든 출력 사진은 흰 배경이며 체크무늬는 출력되지 않습니다. 미리보기는 최종 PNG와 동일한 렌더러를 사용합니다. HTML은 같은 내용과 순서의 독립 문서로, 사진과 치수 실루엣을 내장합니다.

## 품질과 상태

- 이미지 편집은 고충실도 옵션과 색상·무늬·봉제선 보존 지시를 사용하지만 생성형 처리로 원본과 차이가 생길 수 있습니다. 실제 주름·조명 개선과 색상 일치는 원본과 비교해야 합니다.
- 공통 밝기는 보정된 사진에 적용합니다. 대표 사진 밝기를 기준으로 제한된 RGB 공통 배율을 적용하며 실제 색상이나 완전한 조명 일치를 보장하지 않습니다. 밝기 슬라이더를 바꾼 후 `보정된 사진에 공통 밝기 적용`을 누릅니다.
- 성공한 누끼 결과는 같은 세션에서 재사용합니다. 실패해도 이미 완료한 사진은 남깁니다. 편집 내용은 상품별로 이 브라우저에 자동 저장됩니다(보정 결과 재사용 캐시는 새로고침하면 사라짐).
- 전체 PNG는 폭 860px, 최대 높이 30,000px입니다. 더 긴 문서는 사진·문구를 줄이거나 HTML로 저장합니다. 사이즈는 최대 12행, 사진 자리는 최대 14개입니다.

## 브라우저 회귀 검사

`tests/studio-browser.mjs`는 API를 모의 응답으로 대체하여 비용 없이 사진 업로드·붙여넣기·디테일컷 자동 생성 없음·개별 보정·선택형 섹션·6종 치수 가이드·치수 유지·캐시 재사용·HTML/개별 PNG/전체 PNG 및 모바일 화면을 검사합니다. 실제 OpenAI 이미지 품질 검사는 별도입니다.

Playwright는 선택형 검사 도구로 앱 의존성에 추가하지 않았습니다. Chromium이 설치된 환경에서 예를 들어:

```sh
npm run build
PORT=3001 npm start
# 다른 터미널에서
npm install --prefix /tmp/fashion-browser-check playwright
PLAYWRIGHT_MODULE=/tmp/fashion-browser-check/node_modules/playwright/index.mjs node tests/studio-browser.mjs
PLAYWRIGHT_MODULE=/tmp/fashion-browser-check/node_modules/playwright/index.mjs node tests/studio-retry.mjs
```

필요하면 `CHROMIUM_PATH`와 `STUDIO_TEST_URL`을 지정합니다. 테스트 화면 캡처는 `/tmp/fashion-editor-desktop.png`, `/tmp/fashion-editor-mobile.png`에 생성됩니다.

`tests/studio-color.mjs`는 색감 기준 지정·맞추기·되돌리기·API 미호출·새로고침 후 유지를 검사합니다.

`tests/studio-products.mjs`는 여러 상품 자동 저장·복원과 쇼피 ZIP(정사각형 JPG·2MB 이하·사이즈표·listing.txt)을 검사합니다.

`tests/studio-compress.mjs`는 개별 PNG 저장이 2MB 이하로 압축되는지 검사합니다.

`tests/studio-versions.mjs`는 사진별 설정, 무료 되돌리기·다시 적용, 저장 결과 재사용을 검사합니다.

`tests/studio-retry.mjs`는 문구 생성 실패 후 사진 보존·이미지 API 중복 호출 방지·대표 사진 삭제 시 디테일 자리 유지를 검사합니다.
