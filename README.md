# Fashion Studio

React/Vite 의류 상세페이지 편집기. **옷걸이 v2(014)가 기본**입니다. 상품마다 옷걸이 정면·옷걸이 후면 2장만 찍어 편집하고, 디테일컷은 이 2장에서 자동으로 잘라 만듭니다(아래 ‘옷걸이 v2’). 예전 마네킹 방식 화면은 주소 끝에 `?v1`을 붙이면 열립니다(옛 화면 검사용). v1에서는 위쪽 탭이 **상세페이지 제작**(자동 제작 화면)과 **AI모델컷** 두 개이고, v2에서는 AI모델컷 탭을 숨깁니다. 탭을 옮겨도 작업 중인 내용은 유지됩니다. (예전 1차 사진 보정·2차 상세페이지 탭과 브라우저에서 `VITE_` 키를 쓰던 코드는 삭제했고, 모든 키는 서버 환경변수로만 읽습니다.)

## 실행

Node 24에서 검증했습니다. 현재 저장소에는 lockfile이 없습니다.

```sh
npm install --package-lock=false
npm run dev
```

- `npm run build` 후 `npm start`: 빌드된 앱과 AI API를 함께 실행합니다. 기본 주소는 127.0.0.1:3000입니다.
- `npm test`: 실제 API 비용 없이 서버와 상세페이지 문서 구성을 검사합니다.
- `vite preview`만으로는 AI API가 실행되지 않습니다.

서버 환경에 기존 `OPENAI_API_KEY`를 연결합니다. **VITE_ 접두사를 사용하지 않습니다.** 개발 서버는 `.env.local`도 지원하며 프로덕션 서버는 실행 환경 변수를 사용합니다. 모델 선택 변수는 `OPENAI_IMAGE_MODEL`(기본 `gpt-image-1`), `OPENAI_TEXT_MODEL`(기본 `gpt-4.1-mini`)입니다.

## 옷걸이 v2 (014, 기본)

사장님 결정: 마네킹으로 여러 컷을 찍어 일괄 편집하면 결과가 들쭉날쭉해서, **옷걸이 정면·후면 2장만** 잘 찍고 나머지 컷은 이 2장에서 만듭니다. 기준은 `src/utils/appMode.js`의 `HANGER_V2`입니다(브라우저 주소에 `?v1`이 있으면 예전 화면).

- **컷 구성**: 필수 컷은 ‘옷걸이 정면’(hero)·‘옷걸이 후면’(back) 2칸이고 숨길 수 없습니다. 측면·정면 확대·포인트 칸, ‘+ 컷 추가’, Fit guide(모델컷), AI모델컷 탭은 숨깁니다(코드는 남김).
- **v2 기본 보정값**(`V2_RETOUCH`): 받침대 기둥 지우기·마네킹 꼭지 위 정리(`clearFinial`)·마네킹 꼭지 지우기·자동 수평을 끕니다. 옷걸이 사진에는 받침대·꼭지가 없고, 켜 두면 늘어진 끈이나 금색 고리를 잘못 지울 수 있기 때문입니다. 옷걸이는 남기고(고리 끝 살리기·닫힌 틈의 벽 지우기는 그대로), 흰 옷 맑게는 켭니다. 화면에서도 이 옵션들과 Photoroom 생성형 추가 편집(고스트 마네킹·플랫레이·프롬프트)을 숨깁니다.
- **회전 없음**: 수평 맞추기 판을 숨기고 기울기 계산도 하지 않습니다.
- **자동 분류**: `classify`에 `mode:'hanger'`를 보내면 컷 종류를 정면/후면/모름만 받습니다. 같은 옷에 정면(또는 후면)이 2장 이상이면 ‘확인 필요’로 둡니다. 정면은 hero, 후면은 back 칸에 넣고, 그 밖의 사진은 ‘확인 필요 사진’ 칸에 넣습니다.
- **디테일컷 자동 생성**(`src/utils/detailCrops.js` `planDetails`): 보정이 끝난 정면·후면(지금 버전의 2차, 없으면 1차)에서 잘라 냅니다.
  - 긴팔: 넥라인·소재(원단 결)·단추·여밈·밑단·소매 끝. 반팔·조끼·원피스: 소매 끝 없음. 바지: 허리·여밈·소재·밑단.
  - 위치는 옷 영역 비율로 정합니다. 옷걸이 고리는 빼고 폭이 옷의 35% 이상인 첫 줄을 몸판 위쪽으로 봅니다. 소재는 후면 가운데에서 자릅니다. 단추·여밈은 단추 찾기로 2개 이상이 한 줄에 있을 때만 확신합니다. 소매 끝은 소매와 몸판 사이에 틈이 있을 때만 확신합니다. 모두 3:4로 자릅니다.
  - **원본 기준 긴 변 800px**(`DETAIL_MIN_SIDE`)이 안 나오면 키우지 않고 빼고 ‘해상도 부족’으로 표시합니다. 1차 정렬로 옷이 커진 배율도 원본 기준으로 계산합니다. 소재 컷은 92% 이상 옷만 담겨야 합니다.
  - 확신 없는 곳(단추를 못 찾음·소매가 붙음)은 ‘위치 확인 필요’로 뺍니다. ‘확신 없는 위치는 Claude로 찾기’(기본 꺼짐, 유료)를 켜면 정면 사진을 Claude에게 **한 번** 보내 상자만 받습니다(`/api/studio?action=details`, 비용 기록 `details`). 같은 사진은 다시 부르지 않습니다. 사진은 언제나 실제 사진에서 잘라 내고, 새로 그리지 않습니다.
  - **원본 해상도에서 자르기**(014 팀장 결정): 정면·후면은 업로드한 원본(줄이기 전, 최대 6000px, JPG 0.92)을 `slot.original`로 따로 보관합니다. 작업용 사진(2400px)보다 클 때만 보관하며, 직접 올리기·한꺼번에 올리기·드라이브 가져오기 모두 해당합니다.
    - 디테일컷은 이 원본에서 자릅니다(`originalCrop.js`). 1차의 전체 보정 값(색상 밝기·화사하게, 흰 옷 맑게, 색감 이동)은 버전마다 `ops`로 기록해 두고, 잘라 낸 원본에 같은 값으로 다시 적용합니다.
    - 누끼 알파와 2차 보정이 바꾼 픽셀(1차와 다른 곳)은 보정본을 원본 크기로 늘려 씁니다.
    - 결과 긴 변은 최대 2000px입니다(키우지 않음). 원본이 없으면 예전처럼 보정본에서 자릅니다. 카드에 '정면 원본에서 / 보정본에서'가 표시됩니다.
  - 만든 디테일컷(`d-neckline` 등, `derived:{from,detail,box,side}`)은 상품을 다시 열어도 남습니다. 컷마다 ‘상세페이지에 포함’을 끌 수 있습니다. 정면·후면을 다시 보정했으면 ‘디테일컷 다시 만들기’를 누릅니다.
- **자동 보정 흐름**: 정면·후면 → 1차(누끼·옷걸이 유지·흰 배경·색상 기본값) → 색감 통일(정면 기준) → 2차(013 방식, 회전 없음) → 디테일컷 → 최종 → (완성본 저장) 상세페이지.
- **상세페이지 순서**(`documentBlocks`, 지금은 ‘소프트’ 테마): 옷걸이 정면 → 제목·설명 → Back(옷걸이 후면) → Detail(디테일컷, 정해진 순서) → [AI 모델 컷 자리 — `MODEL_CUT_V2.enabled=false`, 지금은 아무것도 그리지 않음] → Size.

### 자동 점검·점검보고서 (014-2)

- 기준: `docs/qa/검증기준서.md`. 숫자는 `src/utils/qaCheck.js`의 `QA`와 같습니다.
- 자동 보정이 상품 하나를 끝내면(최종 뒤) 정면·후면의 누끼·1차·최종과 디테일 보고서로 점검합니다.
  - 항목: 색 변화, 정면·후면 색 차이, 회색 얼룩, 단추 수 변화(2차가 고친 범위 안), 옷걸이 고리 유지, 가장자리 잘림, 떨어진 조각, 옷 면적, 채널별 해상도, 디테일 위치.
  - 결과는 **통과 / 보류 / 불합격**과 이유입니다.
- 보류·불합격이면 `retryPlan`이 고칠 수 있는 항목만 골라 **최대 2회** 다시 편집합니다.
  - 2차가 만든 문제(색·회색·단추): 1회는 같은 1차에서 찾은 곳 중 구김 그림자 펴기만 합니다(저장된 결과 재사용, Claude 추가 호출 없음). 2회는 2차 없이 1차를 최종으로 씁니다.
  - 고리 사라짐: '떨어진 조각 지우기'를 끄고 1차를 다시 합니다.
  - 정면·후면 색 차이: 색감을 강도 100%로 맞춥니다.
  - 가장자리 잘림·떨어진 조각·해상도·디테일 위치는 설정으로 고칠 수 없어 바로 사장님 확인으로 넘깁니다.
- 그래도 통과하지 못하면 '사장님 확인 필요'로 남기고, 완성본 저장 때 상세페이지를 초안으로 저장합니다.
- 결과는 자동 보정 판의 '자동 점검' 표와, 편집 화면의 '자동 점검' 칸(‘이 상품 자동 점검’ 버튼, 무료)에서 봅니다.
- **점검보고서**: 완성본 저장 때 상품 폴더에 `점검보고서.csv`를 함께 올립니다(드라이브 연결 시, 바뀐 것만).
  - 영문 고정 열: `product_id, product_name, checked_at, product_status, attempts, owner_review, cut, check, result, value, limit, reason`
  - 한 줄이 점검 항목 하나입니다.

## Photoroom 누끼·보정

사진 누끼·중앙 정렬은 Photoroom Image Editing API(`image-api.photoroom.com/v2/edit`)로 처리합니다. 서버 환경변수 `PHOTOROOM_API_KEY`가 필요합니다(**VITE_ 접두사 금지**). Photoroom 웹 편집기(app.photoroom.com)의 화면 작업과는 별개이며, API 키와 API 요금제가 필요합니다.

- 기본: 배경 누끼 + 중앙 정렬(선택) + 조명 보정(선택, `lighting.mode=ai.preserve-hue-and-saturation`로 색상 유지). 원본 옷은 그대로 둡니다.
- 선택: 기본 프롬프트(마네킹 오염 정리·구김 펴기·좌우 대칭·기울기 바로잡기)와 직접 입력 프롬프트. 구김 펴기는 Photoroom AI Ironing(`ironing.mode`), 나머지는 Edit With AI(`editWithAI.prompt`)를 사용합니다.
- Photoroom은 호출 1번당 $0.10이며 옵션 수와 관계없이 같으므로, 사진 1장당 한 번에 모두 요청합니다. AI 보정이 거절되면 누끼만 다시 요청(추가 1회)해 결과와 경고를 돌려줍니다.
- OpenAI 엔진을 고르면 Photoroom 누끼 후 OpenAI 이미지 편집으로 프롬프트를 적용합니다.
- 생성형 보정(Edit With AI 출력은 1K)이라 질감이 달라질 수 있어 기본값은 꺼져 있습니다.
- 각 사진의 ‘이 사진 보정 설정’에서 사진별로 다른 설정을 쓸 수 있습니다. 선택하지 않으면 위쪽 기본값을 따릅니다.
- 사진마다 원본·보정본을 최대 8개 버전으로 보관하며 ‘이전으로 / 다시 적용’은 저장된 결과만 바꿔 API를 호출하지 않습니다. 같은 사진·같은 설정으로 다시 누르면 저장된 결과를 재사용합니다(새로고침하면 사라짐).
- ‘개별 PNG 저장’은 2MB를 넘으면 픽셀 크기를 단계적으로 줄여 2MB 이하 PNG로 저장합니다. 작은 사진은 원래 크기 그대로 저장합니다.
- 화면 상단에 Photoroom 남은 이미지 수를 표시합니다(`GET /v2/account`, 과금 없음).
- 화질: 업로드 사진은 긴 변 최대 2400px(JPG, 서버 요청 한도 4.2M자 이내)로 보내고, 배경 제거에 `pr-hd-background-removal: auto`(HD 배경 제거)를 씁니다. 공통 밝기 기본값은 0%입니다.
- 의류 전용 옵션: AI 그림자(`shadow.mode=ai.auto-with-overrides`, `pr-ai-shadows-model-version: 2026-04-15`, 기본 꺼짐), 마네킹 처리(그대로 / 고스트 마네킹 `ghostMannequin.mode` / 플랫레이 `flatLay.mode`). 고스트·플랫레이는 단독 요청이며 1K 출력입니다.
- Edit With AI·고스트 마네킹·플랫레이는 결과가 1K로 작아지며 화면에 경고를 표시합니다. AI 다림질은 2K까지 유지합니다.
- 실제 사진 테스트(1500×2000 마네킹 사진): HD 누끼·AI 다림질은 원본 해상도 유지, 고스트 마네킹은 896×1200이며 없던 목 라벨이 생김, AI 그림자는 서 있는 마네킹 사진에서 왼쪽 아래에 어색한 그림자.
- 색감 통일(API 비용 없음, `src/utils/colorMatch.js`): 보정 컷에서 ‘🎨 이 컷 색감을 기준으로’를 누르면 그 컷 옷의 대표 색(Lab에서 가장 넓은 색 영역, 밝은 무채색 마네킹은 제외)을 기준으로 저장합니다. ‘기준 색감으로 맞추기’는 다른 컷의 대표 색이 기준과 같아지도록 컷 전체의 L·a·b를 같은 양만큼 옮깁니다(강도 슬라이더, 한 번에 L ±14·a/b ±12 제한, 하이라이트·그림자 보호). 결과는 새 버전으로 저장되어 ‘이전으로’로 되돌릴 수 있고, ‘앞으로 보정하는 컷도 자동으로 맞추기’를 켜면 새 보정 결과에 바로 적용합니다. 색감 기준이 있으면 대표 사진 밝기 자동 맞춤은 끕니다.
- 기본 프롬프트 문장은 `src/utils/retouchPresets.js`에서 수정합니다.
- 상품 문구 자동 작성은 계속 `OPENAI_API_KEY`를 사용합니다. 없으면 문구 작성만 건너뜁니다.
- 실제 Photoroom API로 누끼 단독 호출과 누끼+AI 다림질+Edit With AI+조명 결합 호출이 HTTP 200·투명 WebP를 반환하는 것을 테스트 이미지로 확인했습니다. 서버 테스트는 모의 응답으로 요청 형식을 검사합니다.

## 사진 한꺼번에 올리기 (Claude 자동 분류)

상단 ‘사진 한꺼번에 올리기 (자동 분류)’로 여러 옷이 섞인 사진을 최대 24장까지 올리면, 긴 변 512px 작은 사진을 `/api/studio?action=classify`(`server/classify.js`, `@anthropic-ai/sdk`, 모델 `claude-opus-5-5`, 구조화 출력 + 서버 측 거절 대체 `fallbacks: "default"`)로 보내 ① 같은 옷끼리 묶고 ② 컷 종류(정면 전체·정면 상단·정면 하단·측면·후면·원단·모델 착용·기타)를 판별합니다. 옷마다 상품을 만들고(현재 상품이 비어 있으면 첫 옷을 그 자리에) 컷별 칸에 넣습니다. 같은 컷이 두 장이면 추가 칸에 넣습니다. 확신이 낮거나(0.6 미만) 모델이 애매하다고 한 사진은 노란 ‘확인 필요’로 표시하며, 각 사진의 ‘자리 이동’으로 다른 칸과 바꿀 수 있습니다. 서버 환경변수 `ANTHROPIC_API_KEY`가 필요합니다(VITE_ 금지).

## 드라이브 폴더에서 가져오기 + 자동 분류 (009)

상단 ‘드라이브 폴더에서 가져오기 (자동 분류)’를 누르면 구글 ‘파일 선택’ 창(Google Picker)이 열리고, 사진 폴더나 사진 여러 장을 고르면 옷별·컷별로 나눠 상품을 만듭니다.

- **권한**: 기존과 같은 `drive.file` 하나만 씁니다. 선택 창에서 고른 것만 앱이 읽습니다(드라이브 전체 읽기 권한을 추가하지 않음). 폴더를 골랐는데 안의 사진을 읽지 못하면 ‘폴더를 열고 사진을 모두 선택(Ctrl+A)’하라고 안내합니다. 폴더 선택만으로 안의 파일 권한이 생기는지는 공식 문서로 확인하지 못했습니다.
- **필요한 설정(서버 환경변수)**:
  - `GOOGLE_CLIENT_ID`(기존)
  - `GOOGLE_PICKER_API_KEY`(선택 창용 브라우저 공개 키, 구글 콘솔에서 앱 주소·Picker API로만 쓰도록 제한)
  - `GOOGLE_APP_ID`(구글 클라우드 프로젝트 번호)
  
  `status`는 두 값의 형식이 맞을 때만 `googlePicker`로 돌려줍니다. 비밀 키가 아니라 구글이 브라우저에서 쓰도록 만든 키입니다.
- **흐름(화면과 분리, `src/utils/driveImport.js` `runImport`)**: 사진 읽기(분류용 512px) → 묶음 분류 → 옷마다 상품 만들기.
  - 다음 단계(자동 보정)에서 같은 함수를 버튼 없이 이어 부를 수 있습니다.
  - 드라이브·Claude·상품 저장은 함수로 넘겨받습니다(`AutoStudio.jsx`의 `importDeps`).
- **묶음 분류**: 파일 이름(촬영) 순으로 20장씩 Claude에 보냅니다.
  - 둘째 묶음부터는 앞 묶음에서 찾은 옷 중 최근 24벌의 작은 썸네일(256px)을 ‘참고 옷 R1…’로 함께 보내, 같은 옷이면 그 옷에 붙입니다(`server/classify.js` `references`).
  - 묶음마다 비용 기록에 ‘(드라이브 가져오기)’로 남고, 시작 전에 장 수 기준 예상 비용(`classifyEstimate`)을 보여 줍니다.
- **결과**: 옷 하나 = 상품 하나, 칸 배치는 ‘한꺼번에 올리기’와 같은 규칙(`assignSlots`). 확신이 낮은 사진은 ‘⚠ 확인 필요’ 목록에 모이고 ‘상품 열기’로 바로 갑니다.
- **진행·중단·이어하기**:
  - 전체·완료·실패·확인 필요 수와 막대가 보입니다. ‘중단’을 누르거나 오류·창 닫힘으로 멈춰도 진행 상태가 이 브라우저(IndexedDB `fashion-studio-imports`)에 단계마다 저장됩니다.
  - ‘이어서 하기’를 누르면 남은 것부터 이어 갑니다. 이미 분류한 묶음은 다시 보내지 않고, 분류용 사진도 다시 받지 않습니다.
  - 실패한 사진은 다음 실행 때 실패한 단계부터 다시 시도합니다.
- **다시 가져오지 않음**: 상품에 들어간 드라이브 파일 ID를 기록해 두고, 같은 파일은 건너뜁니다(‘가져온 기록 지우기’로 초기화).
- **HEIC**: 브라우저가 열 수 있을 때만 JPG로 바꿔 씁니다. 크롬처럼 열지 못하면 ‘실패’로 표시하고 JPG로 바꿔 올리라고 안내합니다.
- 사진은 분류용(작게)과 상품용(크게)으로 두 번 받습니다. 수백 장을 메모리에 쌓지 않기 위해서입니다.

## 상품 단위 자동 보정 (010)

상품 목록 아래 ‘자동 보정’에서 상품을 고르거나, 드라이브 가져오기가 끝난 화면의 ‘자동 보정 시작’을 누르면, 상품마다·컷마다 끝까지 자동으로 처리합니다.

- **순서**(상품마다, 대표 정면 먼저): 자동 수평 → 1차(누끼 + 받침대 + 정리 + 색상 기본값) → 색감 통일(대표 정면의 옷 색 기준, 상품의 색감 기준으로 저장) → 2차(Claude 찾기 ‘적극’ 4타일 → 신뢰도 0.3 이상 → 구김은 그림자 펴기, 작은 얼룩만 IOPaint, 마네킹·넓은 얼룩 건너뜀 → 결과 검사) → 최종 확정(상품 이미지 다시 그림).
  - 모두 지금 앱 기본값을 씁니다.
  - 흐름은 화면과 분리된 `src/utils/autoPipeline.js`(`planAuto`·`runAuto`)에 있습니다. 실제 처리 단계는 `AutoStudio.jsx`의 `autoSteps`가 저장된 상품 데이터로 합니다.
- **엔진**
  - 누끼는 무료 BiRefNet, 2차는 무료 IOPaint(사장님 PC)로 고정입니다. 시작 전에 둘 다 확인하고, 꺼져 있으면 ‘IOPaint Start를 켜 주세요’ 안내와 함께 시작하지 않습니다.
  - 처리 중 끊기면(연결 실패 오류에 `offline` 표시) 그 컷을 ‘대기(PC 연결 끊김)’로 두고 다음 컷으로 넘어가지 않습니다. 5초마다 다시 확인해 연결되면 같은 단계부터 이어 갑니다. IOPaint는 Claude를 부르기 전에 확인합니다.
  - ‘무료 엔진이 안 될 때 유료(Photoroom)로 대신 처리’(기본 꺼짐)를 켜면 이번 작업의 유료 상한($)을 정합니다. 무료 엔진이 끊긴 단계만 Photoroom(누끼 또는 다림질, $0.10/회)으로 대신하고, 상한을 넘기 전에 멈춥니다.
- **시작 전**: 상품 수, 컷 수(이미 보정한 컷 건너뜀), 예상 시간(BiRefNet 장당 약 30초 + 2차 약 30초 가정), 예상 Claude 비용(컷당 적극 4회), 유료 상한, 무료 엔진 상태를 보여 주고 ‘시작’을 눌러야 진행합니다.
- **진행**: 상품별·컷별 상태(대기·처리 중·대기(PC 연결 끊김)·완료·확인 필요·실패·건너뜀), 진행 막대, 남은 예상 시간(끝난 컷 평균)을 보여 줍니다.
  - 단계마다 상품과 진행 상태를 저장합니다(진행 상태는 IndexedDB `fashion-studio-imports`의 `auto`). 중단·새로 고침 뒤 ‘이어서 하기’를 누르면 끝난 단계를 다시 하지 않습니다.
  - 이미 보정한 컷(2차 결과가 있거나 자동 보정이 확정한 컷)은 건너뛰고, ‘이미 보정한 컷도 다시 보정’을 켜면 처음부터 합니다. 한 컷이 실패해도 나머지는 계속합니다.
- **품질 안전장치 → 확인 필요 목록**: 누끼 옷 면적이 사진의 5% 미만·85% 초과, 자동 수평 신뢰도 25% 미만, Claude가 찾은 곳 0곳 또는 40곳 이상, 색감 통일 뒤에도 대표 컷과 ΔE 10 초과, 유료 대체로 처리한 단계, 2차 결과 검사에서 되돌린 곳·넓은 얼룩처럼 자동으로 고치지 않은 곳(013).
- **끝나면 요약**: 완료·확인 필요·실패·건너뜀 수, 쓴 비용(Claude·유료), 걸린 시간, 확인 필요 목록(‘상품 열기’)과 실패 목록. 모든 비용은 ‘비용 통계’에 기록됩니다.

## 완성본 저장 + 상세페이지 자동 만들기 (011)

자동 보정(010)이 끝나면 이어서 상품마다 완성본과 상세페이지를 만들어 저장합니다(‘끝나면 완성본 저장 + 상세페이지 만들기’, 기본 켬). ‘자동 보정’ 칸에서 상품을 골라 ‘완성본 저장 + 상세페이지만 만들기’로 따로 실행할 수도 있습니다.

- **흐름**(화면과 분리, `src/utils/autoSave.js` `planSave`·`runSave`):
  1. (선택) 비어 있는 제목·설명 자동 작성
  2. 확인 목록
  3. 파일 만들기
  4. 보관·올리기
  
  실제 계산은 `AutoStudio.jsx`의 `saveDeps`가 저장된 상품 데이터로 합니다.
- **만드는 파일**(상품마다):
  - 완성 사진(JPG 2MB 이하, 흰 배경, 상세페이지 순서)
  - 상세페이지 PNG·HTML: 상품의 테마, 새 상품 기본은 ‘소프트’
  - 채널별 묶음 ZIP: 스마트스토어·쿠팡·인스타 4:5·자사몰(07과 같은 규격). 쇼피 ZIP은 보류 지시로 만들지 않습니다.
- **문구**: ‘비어 있는 제목·설명 자동 작성 (OpenAI, 유료)’는 기본 꺼짐입니다.
  - 켜면 시작 전에 ‘상품 n개 × OpenAI 1회(단가 미확인)’를 보여 주고, 제목이나 설명이 빈 상품만 기존 문구 작성(`analyze`, 소재·치수·세탁법 추측 금지)으로 빈 칸만 채웁니다. 비용 기록에 남습니다.
  - 사이즈표가 비어 있으면 ‘—’로 나가고 확인 목록에 ‘사이즈 입력 필요’가 붙습니다.
- **초안**: 자동 보정에서 ‘확인 필요’가 붙은 컷이 있는 상품은 저장은 하되 상세페이지를 `상세페이지_초안.png/html`로 저장합니다.
  - ‘확인 완료 → 정식 저장’을 누르면 `상세페이지.png/html`로 다시 저장합니다(드라이브에서는 같은 파일의 이름만 바뀜). 다시 자동 보정하면 확인을 다시 받습니다.
- **저장 위치**: 만든 파일은 먼저 이 브라우저(IndexedDB `fashion-studio-outbox`)에 보관하고, 구글 드라이브가 연결돼 있으면 바로 올립니다.
  - 드라이브 위치: 작업 폴더 / 상품 이름 폴더(완성 사진은 기존 규칙, 상세페이지·채널 묶음은 종류별 한 파일).
  - 연결돼 있지 않으면 ‘드라이브 연결 후 한 번에 올리기’ 대기열에 남고, 드라이브를 연결하면 한꺼번에 올립니다. 올린 뒤에는 브라우저의 파일 내용을 지워 공간을 아낍니다.
  - 보관 중인 파일은 ‘내려받기’로 받을 수 있습니다.
- **바뀐 것만**: 완성 사진은 기존 지문 비교로 처리합니다. 상세페이지·채널 묶음은 만든 재료(문구·사진·테마·채널)의 지문으로 비교합니다(ZIP은 만든 날짜가 들어가 바이트가 매번 달라지기 때문). 바뀐 것이 없으면 다시 올리지 않습니다.
- **진행**: 상품별 상태(대기·만드는 중·저장됨·실패), 초안 표시, 파일, 확인 목록이 보입니다. 중단·이어하기가 되고, 저장이 끝난 상품은 다시 만들지 않습니다.
- 편집 화면의 자동 저장은 화면의 최신 상태를, 저장 안 된 편집이 있을 때만 저장합니다. 화면이 다루지 않는 값(`detailApproved` 등)은 그대로 둡니다. 오래 걸리는 작업 뒤에 예전 화면 상태로 덮어쓰지 않도록 하기 위해서입니다.

## 얼룩·구김 수정 (Claude 표시 → IOPaint)

역할 분담: **배경 지우기만 Photoroom**, 구김(다림질)·얼룩·먼지·마네킹/벽 흔적 지우기는 **IOPaint(LaMa, 무료)**. 다림질·오염 정리 프리셋은 Photoroom 설정에서 뺐습니다(예전 저장값은 불러올 때 제거).

1. 누끼 후 각 사진의 ‘얼룩·구김 수정 (IOPaint)’ → ‘🤖 수정할 곳 자동 찾기’: 긴 변 1024px JPG를 `/api/studio?action=defects`(`findDefects`, Claude Opus 5.5)로 보내 수정할 곳 상자(0~1000 비율, 종류·설명·확신도)를 받습니다. 디자인 주름·봉제선·로고 등은 표시하지 않도록 지시합니다.
2. 사진 위에 번호 상자를 그려 보여 주고, 확신도 50% 이상만 기본 선택합니다.
2-1. **직접 표시하기(무료)**: ‘✏️ 직접 표시하기’를 켜고 미리보기 사진 위에서 끌어 상자를 그리면(마우스·손가락) 종류(얼룩·구김 등)와 함께 수정할 곳으로 추가됩니다(`manual:true`, 바로 선택). Claude 없이도 쓸 수 있고, Claude로 다시 찾아도 직접 표시는 유지됩니다. 각 표시는 ✕로 삭제합니다(`tests/studio-defects-manual.mjs`).
3. ‘선택한 곳 고치기’(013): 표시 종류에 따라 자동으로 나눠 고치고 새 버전으로 저장합니다(되돌리기 무료). `src/utils/flatten.js`.
   - **구김 = 그림자 펴기(무료, 브라우저 계산)**: 밝기(Lab L)를 저주파(반경 = 긴 변의 0.3%)와 고주파(니트 결)로 나눠, 표시한 곳의 저주파만 주변 옷의 밝기에 맞춥니다(최대 ±18). 색(a·b)과 결은 그대로라 회색이 들어갈 수 없습니다. 주변 옷 색과 다른 픽셀(마네킹 목·꼭지, 단추)은 바꾸지 않습니다.
   - **작은 얼룩·먼지·실밥 = IOPaint**(사장님 PC, 기본 `http://127.0.0.1:8080`, `src/utils/iopaint.js`): 투명한 곳을 가까운 옷 색으로 채운 사진을 보내고(흰 배경이 번지지 않게), 결과는 표시한 곳 안만 쓰고 원래 누끼 알파를 다시 씌웁니다. 사진은 Vercel 서버를 거치지 않습니다.
   - **건너뜀**: 마네킹·벽 흔적(사장님 결정: 마네킹은 남김), 한 변이 사진의 12%를 넘는 넓은 얼룩(확인 필요), 주변이 옷 색이 아닌 곳(마네킹 위로 보이는 표시). 사장님이 직접 표시한 곳은 종류·크기와 상관없이 고칩니다.
   - **단추·부자재 보호(013-B)**: 단추(둥근 테두리, 또는 매끈하고 색이 다른 작은 원)를 찾아, 그 둘레에 닿는 얼룩은 IOPaint로 보내지 않습니다(LaMa가 단추를 지우거나 복제함). IOPaint 뒤에 주변 단추가 흐려졌거나 새로 생겼으면, 구김 펴기 뒤에 뚜렷한 단추가 흐려졌으면 되돌립니다. Claude 찾기 지시에도 단추·지퍼·라벨·끈 등은 표시하지 말고 상자가 덮지 않게 하라고 넣었습니다.
   - **결과 검사**: 고친 곳마다 전·후의 평균 채도가 90% 미만으로 떨어지거나, 16px 칸의 10% 넘게 채도가 85% 미만으로 떨어지거나(회색 얼룩), 결 세기가 75%(얼룩은 60%) 미만이 되면 그곳만 원래대로 되돌리고 ‘확인 필요’로 알립니다. 무채색 옷(채도 6 미만)은 채도 검사를 하지 않습니다.

### IOPaint 설치 (Windows)

앱 상단 ‘사용 도구·비용’에서 `public/iopaint/install-iopaint.bat`을 받아 실행합니다: Python 3.11(없으면 winget) → `%USERPROFILE%\iopaint\venv`에 PyTorch CPU + `iopaint` 설치 → BiRefNet용 패키지와 서버 파일 → 바탕화면 ‘IOPaint Start’ 바로가기(`%USERPROFILE%\iopaint\start-iopaint.bat`: BiRefNet 서버 + `iopaint start --model lama --device cpu --host 127.0.0.1 --port 8080`). 다른 PC도 같은 파일로 설치합니다. IOPaint는 앱을 연 그 PC에서 켜져 있어야 합니다. 크롬이 로컬 네트워크 접근 허용을 물으면 허용합니다. 라이선스: IOPaint Apache-2.0.

### 무료 배경 지우기 (BiRefNet, 내 PC)

누끼·보정 설정의 ‘배경 지우기 엔진’에서 **Photoroom(기본, $0.10/장)** 또는 **BiRefNet(무료)** 을 고릅니다(전체 기본값·사진별 설정 모두). BiRefNet을 고르면 브라우저가 내 PC의 `public/iopaint/birefnet_server.py`(기본 `http://127.0.0.1:8081`, `GET /health`, `POST /remove`)에 사진을 보내 투명 배경 PNG를 받고, 중앙 정렬(여백 6%)은 브라우저에서 합니다. Photoroom 생성형 추가 편집은 BiRefNet일 때 숨깁니다. Photoroom 키가 없어도 동작합니다.

- 모델: `ZhengPeng7/BiRefNet`(MIT, 리비전 고정) PyTorch CPU, 입력 1024px → 마스크를 원본 크기로. 가장자리 옛 배경색 번짐은 blur-fusion 전경 추정으로 제거합니다.
- 실측(이 개발 환경, 4코어): 1500×2000 사진 약 32초, 최대 메모리 약 3.7GB(대기 1.7GB). IOPaint 내장 RemoveBG(rembg ONNX)의 birefnet-general은 최대 약 10GB여서 쓰지 않았습니다.
- 설치: `install-iopaint.bat`이 같은 venv에 `kornia==0.9.0 timm einops`를 더 깔고, 파일 끝에 들어 있는 `birefnet_server.py`·`start-iopaint.bat`을 `%USERPROFILE%\iopaint`에 꺼내 둡니다. 바탕화면 ‘IOPaint Start’는 그 시작 파일을 실행해 BiRefNet과 IOPaint를 한 창에서 함께 켭니다. 첫 실행 때 BiRefNet 모델 약 450MB를 내려받습니다.
- 마네킹 받침대(검은 기둥): BiRefNet은 기둥을 옷의 일부로 남기므로, 기본으로 `src/utils/stand.js`의 `removeStand`가 브라우저에서 지웁니다(설정 ‘마네킹 받침대(검은 기둥) 자동 지우기’, 무료). 사진 맨 아래에서 시작해 곧게 올라가는 좁고 폭이 일정한 무채색 기둥만 찾고, 옷과 만나는 곳은 기둥 양옆 옷 테두리를 이은 선 아래만 지웁니다. 소매·색 있는 끈은 지우지 않습니다(`server/stand.test.js`). BiRefNet 원본 결과는 사진별로 보관해 이 설정만 바꿀 때는 다시 돌리지 않습니다.
- **Photoroom 결과에도 같은 받침대 지우기·누끼 뒤 정리를 적용합니다(기본 켬, 무료).** Photoroom도 기둥을 옷의 일부로 남기는 경우가 있습니다. 결과가 흰 배경(불투명)으로 오면 가장자리에서 이어진 흰색만 투명으로 되살린 뒤(`src/utils/alpha.js`) 정리합니다. Photoroom 원본 결과는 사진에 저장되어, 정리 옵션만 바꿔 다시 처리하거나 새로고침한 뒤 다시 처리해도 Photoroom을 다시 부르지 않습니다(재과금 없음). `tests/studio-photoroom-stand.mjs`가 확인합니다.
- 두 파일을 고친 뒤에는 `npm run sync:iopaint`로 설치 파일을 다시 만듭니다(`server/iopaint-installer.test.js`가 일치를 검사).
- `tests/studio-birefnet.mjs`: 실제 BiRefNet 서버로 앱에서 누끼(`PHOTO_PATH`=배경 있는 원본 JPG).

`tests/studio-iopaint.mjs`는 실제 IOPaint 서버로 얼룩 지우기를 검사합니다(`CUTOUT_PATH`=투명 누끼 PNG, Claude 표시는 모의).

### 찾기 민감도·타일 (사장님 실사용 피드백, 008)

- **기록 항목**: 시각, 상품명, 컷, 기능(수정할 곳 찾기 / 자동 분류 / 기타: Photoroom 누끼·2차 보정, OpenAI 문구), 모델, 민감도, 호출 수(타일 수), 토큰, 비용, 찾은 상자 수, 재사용 여부. 저장된 결과를 다시 쓴 경우(재사용)는 $0·호출 0으로 남깁니다. 타일 찾기가 중간에 실패해도 이미 끝난 타일은 기록합니다.
- **저장**: 이 브라우저의 IndexedDB `fashion-studio-costs`(상품 저장소와 따로라 상품을 지워도 남음). 구글 드라이브가 연결돼 있으면 작업 폴더의 `두손_앱_비용기록.csv`에 덧붙입니다(drive.file 권한, 앱이 만든 파일만). 연결 전 기록은 연결되면 한꺼번에 올립니다. - 비용 표시: 생성 버튼과 ‘모델 후보 2명 생성’ 버튼에 ‘FASHN 크레딧 차감(단가 미확인)’이 붙고, 누르면 새로 만들 장수·얼굴 고정 여부(얼굴 고정은 장당 크레딧 추가)를 보여 주는 확인 창이 뜹니다. 장당 금액은 공식 문서를 직접 확인하지 못해 적지 않았습니다. 확인되면 `ModelCutStudio.jsx`의 `FASHN_COST_LABEL`만 바꾸면 됩니다.
- 중복 과금 방지: 같은 옷 사진·모델·장면·추가 요청·비율·장수·배경으로 다시 누르면 FASHN을 다시 부르지 않고 저장된 결과를 씁니다(‘저장된 결과 재사용 · 추가 비용 없음’ 표시, 확인 창 없음). 결과 주소는 이 브라우저에 70시간 동안 저장됩니다(FASHN 결과는 약 3일 뒤 만료). 같은 설정이 지금 만들어지는 중이면 그 장면은 건너뜁니다. 실패한 작업의 ‘다시 시도’도 저장된 결과가 있으면 그것을 씁니다.
- 원본 비교: 결과 카드마다 ‘원본과 나란히 보기’를 누르면 원본 의류 사진과 생성 결과를 나란히 크게 보여 줍니다(Esc 또는 바깥 클릭으로 닫기).

- FASHN 결과 주소는 약 3일 뒤 만료됩니다. 마음에 드는 컷은 바로 다운로드하세요.
- 서버 환경변수 `FASHN_API_KEY`만 읽습니다(**VITE_ 접두사 금지**, 예전 이름 `VITE_FASHN_API_KEY`는 더 이상 읽지 않습니다).

## 인스타그램 게시 (06)

- 사진을 인스타그램 피드 규격(세로 4:5 · 1080×1350 · JPG)으로 바꿉니다. 순서는 쇼피와 같이 대표 → 모델컷 → 디테일이며 한 게시물에 최대 10장입니다. ‘사진 맞춤’에서 흰 여백(옷 전체) 또는 꽉 채우기(가장자리 잘림)를 고릅니다.
- 캡션은 상품명 → 컬러·사이즈·소재·가격·수량 → 추가 문구 → 구매 안내 → 해시태그 틀로 만듭니다. 입력하지 않은 항목은 줄째로 빠지고, 캡션 칸에서 직접 고칠 수 있습니다. 배송·구매 안내·해시태그·사진 맞춤은 마지막에 쓴 값이 다음 상품의 기본값이 됩니다(이 브라우저에 저장).
- ‘사진·캡션 묶음 다운로드 (ZIP)’와 ‘캡션 복사’는 서버 설정 없이 쓸 수 있습니다(인스타그램 앱에서 직접 올릴 때).
- ‘인스타그램에 지금 게시’는 Instagram API(Instagram 로그인 방식, `graph.instagram.com`)로 게시합니다. 서버 환경변수 세 개가 모두 있어야 버튼이 켜집니다(**VITE_ 접두사 금지**).
  - `INSTAGRAM_ACCESS_TOKEN`: Meta 개발자 앱에서 발급한 액세스 토큰(게시 권한 `instagram_business_content_publish` 포함). 약 60일 뒤 만료되므로 새로 발급해 값을 바꿔야 합니다(자동 갱신은 아직 없음).
  - 토큰 두 종류 지원(012): `IG…`(Instagram 로그인) → graph.instagram.com, `EA…`(Facebook·Meta 비즈니스, 시스템 사용자 토큰) → graph.facebook.com(같은 v25.0). `INSTAGRAM_GRAPH_HOST`로 강제 지정 가능(두 주소만 허용). 붙여넣기 실수(앞뒤 공백·따옴표·줄바꿈·Bearer)는 자동으로 잘라 냅니다.
  - `INSTAGRAM_USER_ID`(인스타 비즈니스 계정 ID, 숫자, 비밀 아님): 있으면 `/me` 없이 그 ID로 확인·게시합니다. Facebook 토큰이면 꼭 필요하고, 없으면 ‘연결 확인’에서 안내합니다. ‘연결 확인’은 계정 이름과 방식·주소만 보여 주고 토큰 값은 보여 주지 않습니다. 결과는 버튼 바로 아래에 크게 보입니다: 성공은 초록 상자 ‘✅ 연결 성공’(계정·방식), 실패는 빨강 상자 ‘❌ 연결 실패’(이유)와 확인 시각(013).
  - `INSTAGRAM_POST_PASSWORD`: 게시 비밀번호. 앱 주소를 아는 다른 사람이 게시하지 못하게 막습니다. 없으면 게시 요청을 모두 거절합니다.
  - `BLOB_READ_WRITE_TOKEN`: Vercel Blob(공개 저장소). 인스타그램은 공개 주소에 있는 사진만 가져가므로, 사진을 잠깐 올렸다가 게시가 끝나면 지웁니다(실패해도 지움, 남은 파일은 하루 뒤 다음 업로드 때 정리).
- 계정 ID는 토큰으로 조회합니다. 조회가 맞지 않으면 `INSTAGRAM_USER_ID`로 직접 지정할 수 있습니다.
- 게시한 날짜와 게시물 주소는 상품에 저장되며, 같은 상품을 다시 게시하려 하면 중복 경고를 띄웁니다. 게시 요청의 응답을 받지 못한 경우에는 실제로 게시됐을 수 있으므로 앱에서 먼저 확인하라고 안내합니다.
- `server/instagram.test.js`(모의 응답)와 `tests/studio-instagram.mjs`(브라우저, 모의 API)로 요청 형식·순서·비밀번호·중복 경고를 검사합니다. **실제 인스타그램 계정으로의 게시는 아직 시험하지 않았습니다**(토큰 발급 전).
- 예약 게시는 아직 없습니다.

## 채널별 내보내기 (07)

`src/components/ChannelExportPanel.jsx`, 계산 `src/utils/channelExport.js`, 규격 `src/utils/channelSpecs.js`. 브라우저 계산만 씁니다(API 비용 없음).

- 완성 사진(최종 버전, 대표 → 모델컷 → 디테일 순서)을 채널 규격에 맞춰 한 번에 만들고, 채널마다 폴더가 나뉜 ZIP 하나로 받습니다. ZIP 안에 `목록.txt`(파일별 크기·용량·원본 컷·규격 출처)가 들어갑니다.
  - 네이버 스마트스토어: 대표 1장 + 추가 최대 9장 (1:1 · 1000×1000)
  - 쿠팡: 대표 1장 + 추가(상세) 최대 9장 (1:1 · 1000×1000)
  - 인스타그램 피드: 최대 10장 (4:5 · 1080×1350)
  - 자사몰: 상세 3:4(1500×2000) 전체 + 썸네일 1:1(1000×1000) 1장
- 모두 흰 배경 · JPG · 2MB 이하입니다. 옷 영역을 찾아 같은 여백(기본 6%, 조절 가능)으로 가운데 배치하고 **옷을 자르지 않습니다**. 가장자리까지 꽉 찬 접사·배경 있는 사진은 사진 전체를 넣고 남는 부분만 흰색으로 채웁니다(기존 `framePhoto`는 이런 컷을 잘라 채우므로 채널용에서는 쓰지 않습니다).
- 파일 이름: `상품명_채널_순번.jpg`(예: `골지티_smartstore_01.jpg`, 대표가 01번). 자사몰은 크기가 두 가지라 `상품명_mall-detail_01.jpg`, `상품명_mall-thumb_01.jpg`입니다. 내려받는 ZIP 파일 이름만 영문(`…_channels_날짜.zip`)입니다(한글 이름을 ‘download’로 바꾸는 브라우저가 있음).
- 규격 확인 수준을 화면에 배지로 표시합니다. **현재 공식 페이지를 직접 열어 확인한 값은 없습니다.**
  - 쿠팡: 공식 Open API 문서·WING 안내 검색 요약 기준(정사각형, 500~5000px, 3MB 이하, 상세 최대 9장, 권장 1000px 이상·흰 배경) — 모두 만족하도록 1000×1000 · 2MB 이하로 만듭니다. 출처 주소는 `channelSpecs.js`에 있습니다.
  - 스마트스토어·인스타: 미확인 → 보수적 기본값.
  - 자사몰: 외부 규격 없음(앱 자체 기준).
- 고른 채널과 여백은 이 브라우저에 기억됩니다. 규격이 바뀌면 `channelSpecs.js` 한 곳만 고칩니다.
- 쇼피는 05 패널의 기존 쇼피 ZIP을 그대로 씁니다(이 기능에는 넣지 않음).

## 편집 흐름

1. 옷 종류와 확인된 상품 정보를 입력하고 대표 정면 사진을 선택합니다.
2. `사진 일괄 누끼·보정 및 문구 제작`으로 배경 제거, 제한적인 주름·조명 정리와 문구 작성을 실행합니다. 디테일컷은 자동으로 만들지 않습니다.
3. 모델컷은 `모델컷 적용`을 선택하고 실제 사진을 넣었을 때만 출력합니다. 옆면·후면·특정 디테일도 실제 사진이 있는 경우만 사용하며, 없는 시점을 생성하지 않습니다.
4. 각 자리에서 JPG/PNG/WebP 파일을 선택하거나 이미지 영역을 클릭하고 Ctrl+V로 클립보드 이미지를 붙여넣을 수 있습니다. 사진당 업로드 제한은 20MB이며, 브라우저에서 긴 변 1600px로 축소합니다. 업로드한 원본은 `보정 전`으로 표시되며 개별 누끼·보정 또는 일괄 처리가 필요합니다. 이미 편집된 외부 사진은 그대로 배치·출력할 수도 있습니다.
5. 정면 확대·상단·하단·원단컷 등 디테일컷은 각 자리에 사진을 직접 넣고 ‘이 사진 누끼·보정’으로 개별 보정합니다. 사진이 없는 자리와 포함 체크를 해제한 컷은 출력에서 빠집니다.
6. 긴팔티셔츠·반팔티셔츠·조끼·원피스·긴바지·반바지에 따라 치수 실루엣과 입력 칸이 바뀝니다. 의류 종류별 입력은 따로 유지합니다. 상의에는 사이즈·가슴단면·총장, 하의에는 사이즈·허리단면·밑위·엉덩이 단면·허벅지 단면·밑단단면·총장이 표시됩니다. 값은 추정하지 않고 빈칸은 `—`로 출력합니다.
7. 제목·설명·사진 제목·섹션 제목·모델 설명·치수 안내를 수정하고 전체 미리보기, 전체 PNG 또는 HTML을 저장합니다. 개별 사진도 PNG로 저장합니다.

최종 순서는 **대표 정면샷 → 상품 문구 → Fit guide(선택) → Detail → Size**입니다. 모든 출력 사진은 흰 배경이며 체크무늬는 출력되지 않습니다. 미리보기는 최종 PNG와 동일한 렌더러를 사용합니다. HTML은 같은 내용과 순서의 독립 문서로, 사진과 치수 실루엣을 내장합니다.

## 품질과 상태

- 이미지 편집은 고충실도 옵션과 색상·무늬·봉제선 보존 지시를 사용하지만 생성형 처리로 원본과 차이가 생길 수 있습니다. 실제 주름·조명 개선과 색상 일치는 원본과 비교해야 합니다.
- 공통 밝기는 보정된 사진에 적용합니다. 대표 사진 밝기를 기준으로 제한된 RGB 공통 배율을 적용하며 실제 색상이나 완전한 조명 일치를 보장하지 않습니다. 밝기 슬라이더를 바꾼 후 `보정된 사진에 공통 밝기 적용`을 누릅니다.
- 성공한 누끼 결과는 같은 세션에서 재사용합니다. 실패해도 이미 완료한 사진은 남깁니다. 편집 내용은 상품별로 이 브라우저에 자동 저장됩니다(보정 결과 재사용 캐시는 새로고침하면 사라짐).
- 전체 PNG는 폭 860px, 최대 높이 30,000px입니다. 더 긴 문서는 사진·문구를 줄이거나 HTML로 저장합니다. 사이즈는 최대 12행, 사진 자리는 최대 14개입니다.

## 구글 드라이브 저장 (여러 컴퓨터에서 이어서 작업)

상품 목록 아래 ‘☁️ 구글 드라이브 저장’(`src/components/DrivePanel.jsx`, `src/utils/googleDrive.js`). 브라우저가 구글 로그인(Google Identity Services, 토큰 약 1시간)으로 **`drive.file` 권한만** 받아 구글 드라이브에 직접 저장합니다(서버를 거치지 않음). 이 권한으로는 앱이 만든 폴더·파일만 보이고 드라이브의 다른 파일은 볼 수 없습니다.

- 처음 연결하면 작업 폴더 이름을 정해 ‘내 드라이브’에 만듭니다(`appProperties.fashionStudio=folder`). 드라이브에서 다른 위치로 옮겨도 됩니다. 다른 컴퓨터에서 같은 계정으로 연결하면 그 폴더를 자동으로 찾습니다(여러 개면 고르기). 폴더는 컴퓨터마다 localStorage에 기억합니다.
- 상품 1개 = 폴더 안 JSON 파일 1개(`appProperties.productId`). 현재 보이는 결과만 올리고 되돌리기 기록·미리보기는 빼서 용량을 줄입니다. 큰 파일도 올라가도록 resumable 업로드를 씁니다.
- ‘이 상품 드라이브에 저장’, ‘드라이브에서 불러오기’, ‘바뀐 뒤 1분 지나면 자동 저장’(연결돼 있는 동안). 상품별로 마지막으로 맞춘 시점을 기억해, 다른 컴퓨터가 그 뒤에 저장했으면 덮어쓰기 전에 묻고 자동 저장은 멈춥니다.
- 설정: Vercel 환경변수 `GOOGLE_CLIENT_ID`(구글 클라우드의 OAuth 웹 클라이언트 ID, 공개 값). `status`가 형식을 확인해 브라우저에 넘깁니다. 승인된 JavaScript 원본에 앱 주소를 넣어야 합니다.
- 저장할 때마다 상품 이름 폴더(`appProperties.fashionStudio=photos`)에 완성 사진을 `01 정면.jpg`처럼 흰 배경 JPG(2MB 이하)로 올립니다. 보정을 마친 컷만, 바뀐 사진만 올리고, 빠진 컷의 사진은 휴지통으로. 작업 파일의 큰 PNG는 WebP로 줄여 올립니다.
- `tests/studio-drive.mjs`: 모의 구글 로그인·모의 드라이브로 컴퓨터 2대 흐름 검사.

## 컷별 보정 화면 (PC: 한 줄에 원본 → 1차 → 2차 → 최종)

- **흰·아이보리 옷 맑게(013-B, 무료, 기본 켬)** — `clearWhite`(`src/utils/colorMatch.js`): 1차 보정에서 옷 밝기 중앙값 70 이상·채도 18 이하인 옷만, 밝은 쪽의 누런 기를 60%·최대 Lab 5까지 덜고 밝은 부분을 최대 +3(L 97 이하) 올립니다. 색 있는 무늬·단추·어두운 곳은 그대로. 설정의 ‘흰·아이보리 옷 맑게’로 끕니다.
- **누끼 뒤 정리 추가(013-B, 무료)** — `src/utils/cleanup.js`: 마네킹 금색 꼭지 맨 위보다 위에 남은 벽 걸이 부품 등을 지웁니다(꼭지·마네킹은 남김). 옷과 떨어진 마네킹 목(밝은 무채색, 사진의 0.1% 이상)은 ‘떨어진 조각’으로 지우지 않습니다. 옷걸이 컷은 원본 사진에서 벽과 다른 가는 선을 따라 지워진 고리 끝을 되살리고(가는 선일 때만), 옷걸이와 옷 사이처럼 닫힌 틈에 남은 벽 색을 투명하게 합니다.
- **자동 수평: 기본 꺼짐 + ‘수평 제안’(013 팀장 결정)** — 상품 3개 실전 시험에서 거의 모든 컷이 양방향으로 틀려(골지·옷걸이·원근을 근거선으로 잘못 고름) 넣자마자 돌리지 않습니다. 사진마다 기울기를 계산해 ‘수평 제안 +n° 적용’ 버튼만 보여 주고 누를 때만 돌립니다(0.1° 슬라이더·‘원래대로 (0°)’는 그대로). 자동 보정(010)도 돌리지 않으며, 예전에 자동으로 돌린 컷은 다음 자동 보정 때 0°로 되돌립니다(사장님이 직접 맞춘 각도는 유지). 설정의 ‘자동 수평 (실험)’을 켜면 아래 예전 방식으로 동작합니다(예전 설정값 `autoLevel`은 쓰지 않음).
- **자동 수평 맞추기(무료, ‘자동 수평 (실험)’을 켰을 때)** — `src/utils/level.js`. 사진을 넣을 때 마네킹 기둥·벽돌 줄·문틀 같은 곧은 세로·가로선을 모아 -10°~+10°(0.1° 단위)에서 선이 가장 곧게 서는 각도를 찾고, 누끼 전에 원본을 바로 세운 사본(`workSource`)으로 누끼를 땁니다(돌리며 생긴 모서리는 벽 색으로 채워 누끼 뒤 흰 배경). 곧은 선이 부족해 신뢰도가 낮으면(25% 미만) 돌리지 않습니다. 원본 칸 아래에서 0.1° 슬라이더·‘자동 수평 다시 계산’·‘0°로’로 바꾸며, 원본 미리보기는 격자와 함께 돌아갑니다. 이미 누끼를 딴 사진은 각도를 바꾸면 바로 다시 처리하는데, Photoroom 결과는 저장된 것을 각도 차이만큼 돌려 쓰므로 다시 과금하지 않습니다. 전체 설정의 ‘자동 수평 맞추기’로 끌 수 있고, 예전에 저장한 사진은 0°(그대로)입니다. 원근(카메라가 위·아래를 보고 찍은 사다리꼴) 보정은 검토만 했고 넣지 않았습니다(보고서 008). **안전장치(013, 사장님 실전 시험에서 확대 컷이 오히려 기울어짐)**: 자동으로 돌리는 컷은 정면 전체·측면·후면뿐이고(분류 결과의 컷 종류 기준, 없으면 칸 이름), 확대·상단·하단·원단·디테일·모델컷은 자동 회전을 하지 않습니다(직접 돌리기는 됨). 정면 전체도 세로선·가로선 두 근거가 모두 있고 같은 방향·1° 이내로 같을 때만, 최대 ±4°까지 돌립니다(넘으면 돌리지 않고 ‘확인 필요’). 돌린 컷은 노란 ‘자동 수평 n° 적용’ 표시와 ‘원래대로 (0°)’ 버튼이 보입니다. 확대·디테일 컷을 직접 돌리면 모서리가 비어 사선으로 잘리지 않도록 그만큼 안쪽으로 잘라 냅니다(`coverScale`, Photoroom 재사용도 같은 배율로 맞춤). `server/level.test.js`(합성 사진 각도 오차), `tests/studio-level.mjs`가 확인합니다.
- **1차 보정 색감 기본값(사장님 결정): 밝기 +20 · 화사하게 +30.** 새로 넣는 사진에 저장되어 1차 보정에 자동 적용됩니다. 사진마다 ‘밝기·화사하게’ 슬라이더로 조절하거나 ‘색감 보정 끄기’(0·0) / ‘기본값으로’ 버튼을 씁니다. 예전에 저장한 사진은 값이 없어 0(그대로)으로 남습니다. 값은 `src/utils/retouchPresets.js`의 `DEFAULT_TONE`. `tests/studio-tone-default.mjs`가 확인합니다.

`src/components/CutRow.jsx`. 컷 종류: 정면, 정면 확대, 정면 상단, 정면 하단, 원단 및 디테일, 디테일 2·3, 측면, 후면, 포인트 1·2(+모델컷, + 직접 이름). 사진이 없는 컷은 숨기고 맨 아래 ‘+ 컷 추가’로 꺼냅니다. 화면 폭 1000px 이하에서는 세로로 쌓입니다.

## 누끼 뒤 정리·보정 개선 (지시서 003)

- **색감 통일 계산** (`src/utils/colorMatch.js`): 옷의 대표 색을 '가장 많은 Lab 칸'에서 **옷 픽셀의 잘라낸 평균**(밝은 무채색 마네킹·아주 어두운 무채색 기둥·옷걸이를 빼고, 위·아래 20%를 버린 평균, 먼 색은 한 번 더 제외)으로 바꿨습니다. 기준과 ΔE 3 이하이면 건드리지 않습니다. 색감 기준 체크·'기준 색감으로 다른 컷 지금 맞추기'·'모든 컷 일관성 맞추기'가 같은 계산을 씁니다.
- **받침대 기둥** (`src/utils/stand.js`): 기준을 바로 아래 20줄로 줄마다 갱신하고 폭은 처음 20줄 기준으로 고정, 직선 맞추기(기울기 약 8° 이하)로 판단해 살짝 기운 기둥도 지웁니다.
- **누끼 뒤 정리** (`src/utils/cleanup.js`, 설정 '누끼 뒤 정리', 브라우저 계산 무료, 두 엔진 공통, Photoroom 재과금 기준에서 제외):
  - 옷과 떨어진 작은 조각 지우기(기본 켬, 전체 불투명 면적의 0.4% 미만 덩어리 + 주변 반투명 찌꺼기).
  - 마네킹 금색 꼭지·목 받침 지우기(**기본 끔 — 사장님 결정으로 남김**): 옷의 색조(대표 색 기준)로 옷/마네킹을 나누고, 세로줄마다 옷이 시작하는 높이 위의 마네킹 픽셀과 그와 이어진 마네킹 픽셀을 지웁니다. 후드를 올린 사진은 옷이 더 위에서 시작하므로 남습니다. 흰·회·검정 옷은 구분할 수 없어 건너뜁니다.
  - 옷걸이: **남기기(기본, 사장님 결정)** — 어깨선 위 가는 선(사진 폭 3% 이하)의 반투명 픽셀을 진하게 해 은색 고리가 끊겨 보이지 않게 함 / 지우기 — 맨 위에서 이어진 '옷 색조가 아닌 어두운 픽셀·어깨선 위 픽셀'을 지움(무채색 옷이면 건너뜀).
- **얼룩·구김 붓으로 칠하기**: 직접 표시의 '표시 방법'에서 '붓으로 칠하기(넓은 구김)'를 고르면 칠한 길을 따라 IOPaint 마스크를 만듭니다(`shape:'stroke'`).
