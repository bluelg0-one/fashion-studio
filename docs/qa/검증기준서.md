# 검증 기준서 — 옷걸이 v2 판매 사진 (014-2)

- 이 문서의 숫자는 앱 코드 `src/utils/qaCheck.js`의 `QA` 값과 같습니다. 하나를 바꾸면 다른 하나도 함께 고칩니다.
- 앱은 자동 보정이 끝나면 상품마다 아래 **자동 측정** 항목을 계산합니다(브라우저 계산, 무료). 화면의 '이 상품 자동 점검' 버튼으로도 할 수 있습니다.
- 결과는 **통과 / 보류 / 불합격**입니다. 항목 중 가장 나쁜 결과가 상품 결과입니다.
- 보류·불합격이고 설정으로 고칠 수 있는 항목이면 설정을 바꿔 **최대 2회** 다시 편집합니다. 그래도 통과하지 못하면 **'사장님 확인 필요'**로 남깁니다. 이때 상세페이지는 초안으로 저장됩니다.
- 점검보고서: 완성본 저장 때 상품 폴더에 `점검보고서.csv`로 저장합니다(드라이브 연결 시). 열 목록은 맨 아래에 있습니다.

## 1. 자동 측정 항목

| 항목 (check) | 무엇을 재나 | 통과 | 보류 | 불합격 | 다시 편집으로 고치기 |
|---|---|---|---|---|---|
| 색 변화 `color_shift` | 1차 → 최종(2차) 옷 대표 색의 차이(Lab ΔE) | ≤ 3 | 3 초과 ~ 6 | 6 초과 | 1회: 얼룩 지우기 없이 구김 그림자 펴기만 · 2회: 2차 없이 1차를 최종으로 |
| 정면·후면 색 차이 `color_pair` | 최종 정면과 후면 옷 대표 색의 차이(ΔE) | ≤ 10 | 10 초과 | — | 후면 색감을 정면에 강도 100%로 맞춤 |
| 회색 얼룩 `gray_blotch` | 1차보다 채도가 85% 미만으로 떨어진 16px 칸 수(원래 채도 6 이상인 칸만) | 0 | 1~3 | 4 이상 | 색 변화와 같음 |
| 단추 수 변화 `buttons` | 2차가 고친 범위(+사진 5% 여유) 안에서 1차와 최종의 단추(확실한 것)를 위치로 짝지어, 잃은 것 + 새로 생긴 것 | 0 | — | 1 이상 | 색 변화와 같음 |

| 옷걸이 자리 패임 `hanger_dent` (옷걸이 '지우기' 설정, 020) | 옷걸이 자리 복원 때 잰 남은 어깨 패임 깊이(윤곽 오목 깊이: 패인 곳 양옆 윗선을 이은 곡선 − 지금 윗선) ÷ 옷 높이. 복원 기록이 없으면 해당 없음 | < 1% | ≥ 1% | — | 없음(복원이 꺼져 있으면 켜고 1차 다시, IOPaint가 꺼져 있었으면 켠 뒤 1차 다시 — 사장님 확인) |
| 옷걸이 고리 유지 `hanger_hook` (옷걸이 '남기기' 설정일 때만) | 누끼에 고리(몸판 위로 옷 높이의 1.2% 이상 솟은 좁은 부분)가 있었는데 최종에도 있는지 | 있음 | — | 사라짐 | '떨어진 조각 지우기'를 끄고 1차 다시(같은 누끼 재사용, 무료) |
| 가장자리 잘림 `edge` | 사진 테두리 2px 안에 옷이 닿은 길이 / 테두리 전체 | < 1% | — | ≥ 1% | 없음(찍은 사진에서 옷이 잘림 → 사장님 확인) |
| 배경 잔여물 `islands` | 옷과 떨어진 조각(사진 면적의 0.05% 이상) 수. 0.4% 미만 조각은 1차에서 이미 지움 | 0 | 1 이상 | — | 없음(끈·벨트 같은 옷의 일부일 수 있어 자동으로 지우지 않음) |
| 옷 면적 `area` | 최종 사진에서 옷이 차지하는 비율 | 5~85% | — | 범위 밖 | 1차 다시 |
| 해상도·규격 `resolution_<채널>` | 원본 옷 긴 변 ≥ 채널 사진 긴 변 × 0.88(여백 6%씩) ÷ 1.25(1.25배까지 키움 허용) | 이상 | 미만 | — | 없음(사진 해상도 문제) |
| 디테일 위치 `details_review` | 디테일컷 중 '위치 확인 필요'로 빠진 수 | 0 | 1 이상 | — | 없음('Claude로 위치 찾기'를 켜고 다시 만들 수 있음, 유료) |
| 디테일 해상도 `details_resolution` | '해상도 부족'으로 뺀 디테일 수(참고용, 결과에 영향 없음) | 항상 통과 | — | — | — |
| 사진 없음 `front_missing` · `back_missing` | 옷걸이 정면(필수) · 후면 | 있음 | 후면 없음 | 정면 없음 | 없음 |

채널별 기준(지금 `channelSpecs.js` 값, 원본 옷 긴 변). 쇼피는 별도 ZIP(정사각형)이라 이 표에 없고, 스마트스토어와 같은 크기 기준으로 보면 됩니다:

| 채널 | 사진 크기 | 통과 기준 |
|---|---|---|
| 스마트스토어 `smartstore` | 1000×1000 | ≥ 704px |
| 쿠팡 `coupang` | 1000×1000 | ≥ 704px |
| 인스타그램 `instagram` | 1080×1350 | ≥ 950px |
| 자사몰 `mall` | 1500×2000 | ≥ 1408px |

- 디테일컷은 만들 때부터 **원본 기준 긴 변 800px 이상**만 만듭니다(그보다 작으면 '해상도 부족'으로 뺌, 확대하지 않음).
- 같은 계산은 2차 보정 때에도 고친 곳마다 합니다. 채도·결 검사에 떨어지면 그곳만 원래대로 되돌립니다(013).

## 2. 눈으로 볼 항목 (자동 측정 없음 — 사장님·팀장 확인)

| 항목 | 보는 법 |
|---|---|
| 실제 상품과 같은지(색·무늬·소재감·핏) | 원본과 최종을 나란히 봅니다. 색은 자동 측정이 있지만 조명에 따른 실제 색 차이는 눈으로만 알 수 있습니다 |
| 하자를 숨기지 않았는지 | 2차가 지운 곳(얼룩·구김)이 실제 하자(구멍·올 풀림)가 아닌지 봅니다 |
| 가장자리 품질 | 니트 털·레이스·얇은 끈이 누끼에서 뭉개지거나 벽색 테두리가 남지 않았는지 봅니다(자동 측정은 떨어진 조각과 잘림만 잼) |
| 옷걸이 자리 복원 (020) | '옷걸이 자리 복원' 전·후 비교에서 채운 곳이 주변 원단과 같은 색·결인지, 넥라인(목 구멍)이 메워지지 않았는지, 원래 없던 부분이 생기지 않았는지 봅니다 |
| 옷걸이 (지우기 설정) | 목 안쪽 옷걸이 바·어깨 끝 걸이 부분이 남지 않았는지, 어깨선·넥라인·라벨·끈이 함께 지워지지 않았는지, 옷걸이가 가리던 곳이 생성으로 채워지지 않고 비어(흰 배경) 있는지 봅니다. 넥라인 디테일컷도 함께 봅니다 |
| 옷걸이 모양 (남기기 설정) | 옷걸이가 자연스러운지, 고리 끝이 투명하게 비지 않았는지 봅니다 |
| 디테일컷 내용 | 넥라인·단추·소매 끝 위치가 맞는지, 소재 컷에 원단만 담겼는지 봅니다 |
| 상세페이지 글 | 제목·설명·사이즈가 맞는지, 사진에 없는 내용(소재·혼용률)을 지어내지 않았는지 봅니다 |

## 3. 점검보고서 열 (영문 고정, CSV · UTF-8 BOM · 한 줄 = 점검 항목 하나)

| 열 | 뜻 |
|---|---|
| `product_id` | 앱의 상품 id |
| `product_name` | 상품 이름 |
| `checked_at` | 점검 시각(ISO 8601, UTC) |
| `product_status` | 상품 결과: `pass` / `hold` / `fail` |
| `attempts` | 다시 편집한 횟수(0~2) |
| `owner_review` | 사장님 확인 필요: `yes` / `no` |
| `cut` | `front` / `back` / `front+back` / `detail` |
| `check` | 항목 이름(위 표의 영문 이름, 채널 해상도는 `resolution_smartstore` 등) |
| `result` | 항목 결과: `pass` / `hold` / `fail` / `na`(해당 없음, 예: 옷걸이 남기기 설정에서 누끼에 고리가 없던 옷) |
| `value` | 잰 값(ΔE, 칸 수, 개수, %, px) |
| `limit` | 통과 기준 |
| `reason` | 통과가 아니면 쉬운 말 이유, 통과면 빈칸 |
