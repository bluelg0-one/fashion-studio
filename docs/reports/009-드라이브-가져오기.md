# 지시서 009 보고 — 구글 드라이브 폴더에서 한꺼번에 가져오기 + 자동 분류

작성: 2026-11-24 · 브랜치 `claude/integration-002`

## 먼저: 사장님이 구글 콘솔·Vercel에서 해 주실 일

드라이브 권한은 지금과 같은 **‘앱이 만들거나 사장님이 고른 파일만’(drive.file)**을 그대로 씁니다. 드라이브 전체를 읽는 권한을 새로 받지 않으므로 **구글 동의 화면 수정이나 구글 심사가 필요 없습니다.** 대신 구글의 ‘파일 선택 창’을 쓰기 위한 설정이 3가지 늘었습니다.

> 이 3가지는 작업 환경에서 구글 공식 문서가 열리지 않아, 지금까지 알려진 방법으로 정리했습니다. 화면 이름이 조금 다를 수 있습니다. 막히시면 화면을 찍어 보내 주세요.

0. (이미 대기 중인 일) 구글 콘솔 → **API 및 서비스 → 사용자 인증 정보 → OAuth 클라이언트 ID**를 엽니다. ‘승인된 JavaScript 원본’에 앱 주소를 넣어 주세요. 이게 되어야 드라이브 연결이 됩니다.
1. 구글 콘솔(지금 로그인용 클라이언트 ID를 만든 같은 프로젝트) → **API 및 서비스 → 라이브러리**에서 **‘Google Picker API’**를 찾아 **사용**을 누릅니다.
2. **API 및 서비스 → 사용자 인증 정보 → ‘+ 사용자 인증 정보 만들기’ → API 키**를 누릅니다. 만들어진 키의 **‘키 제한’**을 아래처럼 정합니다.
   - 애플리케이션 제한: **웹사이트(HTTP 리퍼러)** → 앱 주소(예: `https://앱주소/*`)
   - API 제한: **Google Picker API**만
   
   그다음 Vercel 환경변수 **`GOOGLE_PICKER_API_KEY`**에 이 키를 넣습니다.
   - 이 키는 비밀번호 같은 비밀 키가 아니라, 구글이 브라우저에서 쓰라고 만든 공개 키입니다. 위의 제한을 걸어 두면 다른 사이트에서 쓸 수 없습니다.
3. 구글 콘솔 첫 화면(대시보드)의 **‘프로젝트 정보 → 프로젝트 번호’**(숫자만)를 Vercel 환경변수 **`GOOGLE_APP_ID`**에 넣습니다.
4. Vercel에서 **다시 배포**합니다.

설정 전에는 버튼이 회색으로 잠기고, 어떤 설정이 빠졌는지 화면에 표시됩니다. 그동안은 기존 ‘사진 한꺼번에 올리기’(24장까지)를 쓰시면 됩니다.

### 권한 방법을 고른 이유
| 방법 | 사장님 할 일 | 단점 |
|---|---|---|
| **선택 창(Picker) + drive.file (선택)** | 위 1~3 (Picker 사용 설정, 키 1개, 번호 1개) | 사장님이 고른 것만 읽음(오히려 안전) |
| drive.readonly 추가 | 동의 화면에 범위 추가 + 드라이브 전체 읽기라서 **구글 심사가 필요할 수 있음**, 로그인할 때 ‘드라이브 전체 보기’ 경고 | 앱이 드라이브 전체를 볼 수 있음 |

‘drive.readonly는 구글 심사가 필요한 제한 범위’라는 점도 공식 문서로 다시 확인하지는 못했습니다(문서가 열리지 않음). 그래도 사장님 할 일이 가장 적고 권한도 가장 좁은 선택 창 방식을 골랐습니다.

## ① 무엇이 되는지 (화면에서 해 볼 방법)

1. 상품 선택 줄 아래 **‘드라이브 폴더에서 가져오기 (자동 분류)’**를 누릅니다. 처음이면 구글 로그인 창이 뜹니다.
2. 구글 선택 창에서 **사진 폴더**(또는 사진 여러 장)를 고릅니다.
3. **‘새 사진 N장 · 예상 비용 약 $…~$… (Claude 분류 k번)’**이 보입니다(46장이면 약 $0.12~$0.27). **‘분류 시작’**을 눌러야 비용이 드는 분류가 시작됩니다.
   - 이미 가져온 사진은 ‘이미 가져온 사진 n장 건너뜀’으로 빠집니다.
   - 사진이 아닌 파일은 제외됩니다.
4. 진행 막대와 **전체 · 완료 · 실패 · 확인 필요** 수가 보입니다.
   - 사진은 파일 이름(촬영) 순서로 **20장씩** Claude에 보냅니다.
   - 둘째 묶음부터는 앞에서 찾은 옷(최근 24벌)의 작은 사진을 함께 보내, 묶음 사이에 같은 옷이 나뉘어도 **한 상품으로 합칩니다.**
5. 끝나면 **옷 하나마다 상품이 하나씩** 만들어지고, 사진이 컷 칸(정면·후면·측면·원단…)에 들어갑니다. 지금의 ‘한꺼번에 올리기’와 같은 규칙입니다. 첫 상품이 바로 열립니다.
6. 확신이 낮은 사진은 **‘⚠ 확인 필요’ 목록**에 파일 이름·옷·컷·이유와 함께 모입니다. **‘상품 열기’**로 그 상품에 바로 갑니다.
7. **중단·이어하기**
   - ‘중단’ 버튼을 누르거나, 오류나 창 닫힘으로 끊겨도 진행 상태는 저장됩니다.
   - **‘이어서 하기’**를 누르면 남은 것부터 이어 갑니다. 이미 분류한 묶음은 다시 보내지 않아 비용이 다시 들지 않습니다.
   - 실패한 사진은 다시 누르면 다시 시도합니다.
8. 분류 비용은 ‘비용 통계’에 **‘(드라이브 가져오기)’**로 묶음마다 기록됩니다.
9. 다음 단계(010 자동 보정)에서 버튼 없이 이어 붙일 수 있게, ‘가져오기 → 분류 → 상품 만들기’를 화면과 분리된 함수로 만들었습니다(`src/utils/driveImport.js`의 `runImport`).

화면 캡처 2장(시작 전 계획 화면, 끝난 뒤 결과·확인 필요 목록)을 채팅으로 보내 드립니다. 모의 사진이라 옷 이름이 ‘옷0, 옷1…’입니다.

## ② 테스트 결과

실제 Claude·구글 드라이브는 한 번도 부르지 않았습니다. 구글 로그인·선택 창·드라이브·Claude 모두 모의 응답으로 검사했습니다.

- `npm test`: **108개 모두 통과**(새로 7개).
  - 묶음 분류: 45장 → 20·20·5, 둘째 묶음에 앞 옷 전송, 묶음에 걸친 옷도 한 상품
  - 중단 후 이어하기: 남은 25장만 분류하고 사진은 다시 받지 않음
  - 이미 가져온 파일 건너뛰기, 실패 재시도, 칸 배치 규칙, 장 수별 예상 비용
  - 서버가 참고 옷 R1…을 보내고 결과를 원래 옷 번호로 바꿔 주는지
  - 상태 응답에 선택 창 키·번호를 형식이 맞을 때만 넣는지, 비밀 키는 내보내지 않는지
- `npm run build`: 통과.
- 새 브라우저 검사 `tests/studio-drive-import.mjs`: **통과.**
  - 폴더(목록 2쪽, 46장)를 골라 예상 비용을 표시하고, 시작 전에는 호출하지 않음
  - 둘째 묶음에서 서버 오류(529)로 멈춤 → ‘이어서 하기’로 남은 묶음만 분류(분류용 사진 재다운로드 0장)
  - 옷 8벌 = 상품 8개(묶음에 걸친 옷도 6장 모두 한 상품)
  - 확인 필요 1장 → ‘상품 열기’로 이동, HEIC 1장은 실패 안내
  - 비용 기록 3줄(실패한 호출은 기록 없음)
  - 같은 폴더를 다시 고르면 45장 건너뜀, 안을 못 읽는 폴더는 Ctrl+A 안내, 선택 창 취소 시 아무것도 안 함
- 이번에 고친 ‘한꺼번에 올리기’와 영향받는 기존 브라우저 검사(classify, products, costs, browser, cuts, versions, retry)도 **모두 통과**했습니다.

## ③ 아직 안 된 것·위험한 점

- **실제 구글 선택 창·드라이브·Claude로는 확인하지 않았습니다**(지시대로 모의 응답만 사용, 드라이브 연결도 아직 막혀 있음). 설정이 끝나면 실제 폴더로 한 번 확인이 필요합니다.
- **폴더를 고르면 그 안의 사진까지 읽을 수 있는지**(drive.file 권한에서)는 구글 공식 문서로 확인하지 못했습니다.
  - 읽지 못하면 화면에 ‘선택 창에서 폴더를 열고 사진을 모두 선택(Ctrl+A)해 다시 골라 주세요’가 뜹니다. 그 방법이면 확실히 됩니다.
  - 실제로 해 보고 결과를 알려 주시면 안내 문구를 맞추겠습니다.
- 선택 창이 API 키와 프로젝트 번호를 모두 요구한다는 점도 공식 문서로 다시 확인하지 못했습니다.
- **HEIC(아이폰 기본 사진)**는 크롬에서 열리지 않아 ‘실패’로 표시합니다. 아이폰 설정에서 ‘높은 호환성(JPG)’으로 찍거나 JPG로 바꿔 올려 주셔야 합니다.
- **분류 정확도**
  - 묶음 사이 같은 옷 판단은 앞에서 찾은 옷 중 **최근 24벌**만 비교합니다. 같은 옷 사진이 폴더에서 멀리 떨어져 있으면 따로 상품이 될 수 있습니다.
  - 사진은 파일 이름 순서로 처리하므로, 같은 옷을 연달아 찍으면 가장 정확합니다.
  - 실제 사진으로 정확도를 아직 재 보지 않았습니다.
- 사진은 분류용(작게)과 상품용(크게)으로 **두 번** 받습니다. 수백 장을 한꺼번에 메모리에 올리지 않기 위해서입니다. 드라이브 다운로드는 무료이고, 시간만 조금 더 걸립니다.
- 진행 상태와 ‘이미 가져온 사진’ 기록은 **이 PC의 브라우저에만** 저장됩니다. 다른 PC에서 같은 폴더를 가져오면 상품이 또 만들어집니다.
- 상품당 사진 칸은 지금 화면과 같고, 같은 컷이 여러 장이면 ‘추가 칸’에 들어갑니다. 자동 보정 연결은 다음 지시서(010) 범위입니다.
