# 019 — 모델 보관함 (여러 모델 저장·선택)

- 기준 브랜치: `claude/hanger-v2`(2f107b9). 작업 브랜치: `claude/integration-002`.
- 실제 FASHN·Google·드라이브 호출은 하지 않았습니다(모의 응답만). 유료 호출 0회입니다.

## 무엇이 되나

사장님: "새로 만든 모델을 드라이브에 여러 명 저장해 두고, 그중에서 골라 착샷을 만들고 싶다."

- **구도별 모델 목록**: 018의 '구도별 기본 모델 사진 1칸'을 '모델 목록'으로 바꿨습니다(상반신 / 하반신 / 원피스). 모델컷 탭의 '② 모델 보관함'에 지금 구도의 모델이 작은 사진 카드로 보입니다. 다른 구도의 모델 수도 함께 표시합니다.
- **저장**
  - 방법: 사진 올리기, 'AI로 새 모델 만들기' 후보의 '기본 모델로 저장', 모델컷 결과의 '기본 모델로 저장'(이미 있는 버튼 재사용)
  - 지금 구도의 목록에 들어갑니다. 저장하기 전에 '새 모델 이름' 칸에 이름을 쓸 수 있고, 비우면 '모델 1, 2…'입니다.
  - 저장한 모델은 바로 골라집니다.
- **이름 바꾸기·삭제**: 카드마다 '이름'·'삭제' 버튼이 있습니다. 삭제는 확인 창을 거치고, 드라이브에서도 지워집니다.
- **선택**
  - 카드를 눌러 고릅니다. '선택 안 함(새 모델 생성)' 카드도 있습니다.
  - 처음 고른 모델이 그 구도의 기본값이 되고, 상품마다 마지막으로 고른 모델을 기억합니다.
  - 고른 모델이 없으면 018처럼 '새 모델 생성'(product-to-model)으로 동작합니다.
  - 엔진 칸 표시는 "지금 방식: 고정 모델 · 장당 약 $0.075 (보관함 모델 '봄 모델'에 옷 입히기)"처럼 나옵니다.
  - Google 가상 피팅도 고른 모델 사진을 씁니다.
- **018 데이터 이전**: 브라우저나 드라이브에 018 형식(구도별 사진 1장)이 있으면 읽을 때 그 구도 목록의 첫 모델 '모델 1'로 옮기고, 그 구도의 기본 선택으로 둡니다. 사진은 그대로라 데이터 손실이 없습니다.
- **드라이브 동기화**(작업 폴더가 연결돼 있을 때)
  - `두손_기본모델.json`을 목록 형식(v2)으로 확장했습니다. 이 파일에는 목록·이름·파일 ID·수정 시각·삭제 기록만 둡니다.
  - 모델 사진은 작업 폴더 아래 `모델보관함` 폴더에 `{모델 id}.jpg`로 따로 저장합니다(파일이 커지지 않게).
  - 언제 맞추나: 모델컷 탭을 열 때와 보관함을 바꿀 때(저장·이름·삭제)
  - 병합 규칙
    - 모델마다 나중에 바꾼 쪽을 씁니다(018의 '최근 수정 기준' 유지).
    - 드라이브에만 있는 모델은 사진을 받아 오고, 브라우저에만 있는 모델은 JPG로 올립니다.
  - 삭제는 지운 시각을 남겨, 다른 PC와 병합해도 되살아나지 않습니다. 지운 모델의 JPG는 드라이브 휴지통으로 보냅니다.
  - 목록이 바뀌지 않았으면 json을 다시 쓰지 않습니다.
- 계산은 `src/utils/modelLibrary.js`(이전·추가·이름·삭제·선택·병합·동기화)에, 드라이브 함수는 `src/utils/googleDrive.js`에 있습니다(모델 폴더·JPG 올리기/받기/휴지통).

## 아직 안 된 것·위험한 점

- **실제 드라이브로는 실행해 보지 않았습니다.** 드라이브 로그인을 화면 검사에서 흉내 낼 수 없어서, 동기화 순서는 가짜 드라이브 함수로만 검사했습니다.
- 모델 사진은 이 브라우저 저장 공간(localStorage, 보통 약 5MB)에도 들어갑니다. 사진 한 장이 약 100~300KB라 모델이 20명쯤 넘으면 '저장 공간 부족' 안내가 뜰 수 있습니다. 그때는 안 쓰는 모델을 지워 주세요(드라이브 저장본은 영향 없음).
- 두 PC에서 같은 모델 이름을 거의 동시에 바꾸면 나중에 맞춘 쪽 이름이 남습니다.
