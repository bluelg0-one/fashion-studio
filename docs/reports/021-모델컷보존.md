# 021 — 모델컷 결과 보존 + 드라이브 자동 저장 + 3일 뒤 임시본 정리

- 기준 브랜치: `claude/hanger-v2`(75447eb). 작업 브랜치: `claude/integration-002`(020 커밋 68b5655 위). 020은 이 지시를 받기 전에 이미 끝나 올라가 있었습니다.
- 실제 FASHN·드라이브 호출은 하지 않았습니다(모의 응답만). 유료 호출 0회입니다.

## 1. 원인(확인함)

이전 코드(75447eb)를 따로 빌드해 같은 순서로 재현했습니다(모의 FASHN).

| 동작 | 이전 | 지금 |
|---|---|---|
| 앱 안 탭 이동(원본 보정·상세페이지 → 모델컷) | 4장 남음 | 4장 남음 |
| **페이지 새로고침 뒤 같은 상품** | **0장(사라짐)** | **4장 남음** |

- 앱 안의 탭 이동으로는 사라지지 않았습니다. 모델컷 화면은 숨겨질 뿐 계속 남아 있습니다.
- 결과는 화면 메모리에만 있어서 **페이지가 새로 열리면** 사라졌습니다. 가장 가능성 높은 경우는 크롬이 오래 안 본 브라우저 탭을 메모리 절약으로 정리했다가 돌아올 때 다시 여는 것입니다. 사장님의 "잠깐 다른 탭에 갔다가 돌아오면"과 같은 상황입니다. 새로고침, 앱 업데이트(배포), 노트북 절전도 같습니다.
- 진행 중 작업 ID와 모델 후보도 메모리에만 있었습니다. 결과 주소(FASHN)는 약 3일 뒤 만료되는데, 재사용 기록에는 주소만 있었습니다.

## 2. 고친 것

- **즉시 저장**: 착샷 결과, 모델 후보, 진행 중 작업(작업 ID 포함)을 생기는 순간 이 브라우저 IndexedDB(`fashion-studio-modelcuts`)에 상품별로 저장합니다. 모델컷 탭은 지금 상품의 결과만 보여 줍니다.
- **이미지째 저장**: 결과가 나오면 서버 `fetch` 경로로 이미지를 받아 data URL로 저장합니다. 원래 주소는 `sourceUrls`에 남겨 '이 상품 모델컷으로 저장'의 원본 결과 주소로 씁니다.
- **이어 받기**: 다시 열 때 작업 ID가 있는 진행 중 작업은 상태 확인만 다시 해서 완료합니다. **다시 과금하지 않습니다**(검사에서 run 호출 수가 늘지 않음).
  - 작업 ID가 없는 작업(대기 중이라 아직 시작 전, 과금 없음)은 '중단됨(아직 시작 전 · 과금 없음) · 다시 시도'로 보입니다.
  - Google은 응답을 바로 받는 방식이라 중간에 끊기면 '결과를 받지 못함(과금됐을 수 있음 — 비용 기록 확인)'으로 표시합니다.
- **드라이브 자동 저장**: 연결돼 있으면 결과를 작업 폴더 `모델컷_임시/상품명`에 JPG로 바로 올립니다. 파일 속성에 상품 id·결과 id·장면을 남깁니다.
  - 연결이 안 돼 있으면 결과에 '아직 안 올림'으로 남겨 두고, 연결된 뒤 모델컷 탭을 열 때 올립니다.
  - 다른 PC에서 모델컷 탭을 열면 그 상품의 드라이브 파일을 불러와 보여 줍니다.
  - 011 대기열(outbox)을 그대로 쓰지 않은 이유: 그 대기열은 상품당 한 칸(완성본·상세페이지 묶음)이라 모델컷을 넣으면 완성본 대기분을 덮어씁니다. 같은 방식(브라우저에 먼저, 연결되면 올림)을 모델컷 기록 안에 따로 두었습니다.
- **3일 뒤 정리**
  - 011 완성본 저장에서 초안이 아니면 그 시각(`finalAt`)을 기록합니다.
  - 앱을 열 때와 그 뒤 하루 한 번 검사합니다. 정식 저장 뒤 3일이 지나면 그 상품의 **임시** 결과를 브라우저에서 지우고, 드라이브 파일은 **휴지통**으로 보냅니다. 연결이 안 돼 있으면 지울 파일 ID를 모아 두었다가 연결되면 보냅니다.
  - 진행 중 작업은 지우지 않습니다.
  - 3일 안이면 모델컷 탭에 **'○일 뒤 임시 모델컷 n장 자동 삭제'** 와 **'보관 연장 (다시 3일)'** 버튼이 나옵니다.
  - 지우지 않는 것: '이 상품 모델컷으로 저장'한 컷(상품 데이터), 모델 보관함(019), 상세페이지 사진. 모두 다른 저장소입니다.
- '목록 비우기'는 돈을 내고 만든 결과라 확인 창을 거친 뒤 이 브라우저 기록을 지웁니다.
- 결과를 저장하지 못하면(저장 공간 부족) 빨간 안내를 띄웁니다.

## 3. 다른 탭의 유료 결과(5번)

| 결과 | 저장 위치 | 판정 |
|---|---|---|
| Photoroom 누끼 원본(`rawCut`)·1차·2차 | 상품 데이터(IndexedDB) | 자동 저장(0.8초 뒤) |
| Photoroom 2차 재사용 기록 | 이 브라우저 | 새로고침 후에도 재사용(013) |
| Claude 분류 결과 | 만들자마자 상품으로 저장 | 손실 없음 |
| Claude 수정할 곳(`defects`)·디테일 위치(`detailReport`) | 상품 데이터 | 자동 저장 |

- 남아 있던 위험: 자동 저장을 0.8초 기다리는 사이 브라우저 탭이 정리되면 마지막 결과가 저장되지 않을 수 있었습니다.
  - 그래서 **브라우저 탭을 옮기거나 닫는 순간(visibilitychange·pagehide) 기다리던 자동 저장을 바로 하게** 했습니다.
  - 다만 결과가 오기 전에(요청 도중) 탭이 정리되면 그 호출 결과는 받을 수 없습니다. Photoroom은 응답을 바로 주는 방식이라 이어 받을 작업 ID가 없습니다.
- 앱 안의 탭 이동으로는 원본 보정·상세페이지 상태가 사라지지 않습니다. 017부터 한 화면이 상태를 들고 있고, 검사로 확인했습니다.

## 5. 아직 안 된 것·위험한 점

- **드라이브 자동 저장·불러오기·휴지통은 실제 드라이브로 실행해 보지 않았습니다.** 드라이브 로그인을 화면 검사에서 흉내 낼 수 없어서, 정리 계산과 파일 속성으로 기록 만들기만 단위 검사했습니다.
- 드라이브 연결 전에 만든 결과는 연결한 뒤 **모델컷 탭을 열어야** 올라갑니다.
- 결과 사진이 이 브라우저 저장 공간을 씁니다(1장 약 0.2~1MB). 3일 정리 전까지 많이 만들면 공간이 부족할 수 있고, 그때는 빨간 안내가 뜹니다.
- 정리는 앱이 열려 있을 때만 돌아갑니다. 앱을 오래 안 열면 다음에 열 때 지웁니다.
- 원본 보정의 Photoroom 호출 도중 브라우저 탭이 정리되면 그 호출 결과는 받을 수 없습니다(위 3절).
