# 보고서 005 — 채널별 규격 한 번에 출력

- 브랜치: `claude/integration-002` (002·002-후속 위에 이어서)
- 작성일: 2026-11-23
- PR은 만들지 않았습니다. 쇼피 코드는 수정하지 않았습니다(기존 쇼피 ZIP 그대로).

## ① 무엇이 되는지 (화면에서 해 볼 방법)

**상세페이지 제작** 탭의 왼쪽 편집 영역 맨 아래, 06 인스타 밑에 **07 · 채널별 내보내기**가 생겼습니다.

1. 보낼 채널을 체크합니다(기본은 4개 모두). 채널마다 규격과 확인 수준 배지가 보입니다.
2. ‘옷 둘레 여백’을 고릅니다(기본 6%).
3. **‘채널별 묶음 다운로드 (ZIP)’**를 누르면 ZIP 하나가 내려받아집니다. 브라우저에서 계산하므로 비용이 없습니다(‘브라우저 계산 · 무료’ 표시).

ZIP 안의 구성(사진 2장일 때 예시):

```
상품명/
  smartstore/  상품명_smartstore_01.jpg (대표), 상품명_smartstore_02.jpg (추가)
  coupang/     상품명_coupang_01.jpg (대표), 상품명_coupang_02.jpg (추가)
  instagram/   상품명_instagram_01.jpg, _02.jpg            (4:5 · 1080×1350)
  mall/        상품명_mall-detail_01.jpg, _02.jpg (3:4 · 1500×2000), 상품명_mall-thumb_01.jpg (1:1)
  목록.txt     파일별 크기·용량·원본 컷·규격 설명·출처 주소
```

- 쓰는 사진: 완성 사진(최종 버전)을 대표 → 모델컷 → 디테일(‘상세페이지에 포함’ 체크한 컷) 순서로 씁니다. 쇼피·인스타와 같은 순서입니다.
- 모두 **흰 배경 · JPG · 2MB 이하**로 만듭니다. 옷이 있는 영역을 찾아 **같은 여백으로 가운데 배치**합니다. 누끼(투명 배경)와 흰 배경 사진 모두 이렇게 처리합니다.
- **옷을 자르지 않습니다.** 가장자리까지 꽉 찬 접사나 배경이 있는 사진은 사진 전체를 넣고, 남는 부분만 흰색으로 채웁니다.
  - 기존 `framePhoto`는 이런 컷을 비율에 맞춰 잘라 채웁니다. 그래서 같은 방식(옷 영역 → 같은 여백 → 가운데)을 쓰되 자르지 않는 버전을 `channelExport.js`에 따로 만들었습니다. `framePhoto` 자체는 바꾸지 않았습니다.
- 고른 채널과 여백은 이 브라우저에 기억됩니다.

화면 캡처: `docs/reports/img/channel-panel.png` (모의 사진).

### 규격과 출처 (모두 `src/utils/channelSpecs.js` 한 파일에 있음)

이 작업 환경에서는 smartstore.naver.com, coupangcorp.com, facebook.com 접속이 막혀 있습니다. 그래서 **공식 페이지를 직접 열어 확인한 값은 하나도 없습니다.** 확인 수준을 네 가지로 나눠 화면 배지와 코드 주석에 적었습니다.

| 채널 | 만드는 사진 | 확인 수준 | 근거 |
|---|---|---|---|
| 네이버 스마트스토어 | 대표 1 + 추가 최대 9 · 1:1 · 1000×1000 · JPG · 2MB 이하 · 흰 배경 | **미확인 · 보수적 기본값** | 공식 수치를 찾지 못함(검색에는 제3자 글만 나옴). 추가 이미지 9장 상한도 미확인 |
| 쿠팡 | 대표 1 + 추가(상세) 최대 9 · 1:1 · 1000×1000 · JPG · 2MB 이하 · 흰 배경 | **검색 요약 기준 · 원문 미열람** | 공식 문서 검색 요약: 대표이미지 정사각형, 3MB 이하, JPG·PNG, 500~5000px, 상세 최대 9장 / WING 안내: 권장 1000×1000 이상, 흰 배경에 상품만, 10MB 이하. 두 기준을 모두 만족하도록 만듦 |
| 인스타그램 피드 | 최대 10장 · 4:5 · 1080×1350 · JPG · 2MB 이하 | **미확인 · 보수적 기본값** | 06 인스타 패널(인스타 브랜치) 값과 같게 맞춤. Meta 공식 문서는 이번에 확인 못 함 |
| 자사몰 | 상세 3:4 1500×2000(전체) + 썸네일 1:1 1000×1000(1장) | 자사몰 자체 기준 | 외부 규격 없음. 기존 정렬 기능의 3:4 크기와 같음 |

## ② 테스트 결과 (실행한 명령과 결과)

Node v22.23.5로 실행했습니다(Node 24로는 실행해 보지 않음). API 호출은 없습니다.

```
npm test        → tests 60, pass 60, fail 0  (server/channels.test.js 2개 추가)
npm run build   → ✓ built
```

- `server/channels.test.js` 2개:
  - 모든 규격이 흰 배경 JPG, 2MB 이하, 1000px 이상이고 비율과 크기가 맞는지, ‘검색 기준’ 값에는 출처가 있는지
  - 사진 배정 규칙: 대표·썸네일은 첫 장, 추가는 나머지, 장수 상한(스마트스토어 추가 9, 인스타 10)
- `tests/studio-channels.mjs` (새 브라우저 검사):
  `PASS: 4 channel folders, 상품명_채널_순번 names (상품 1), sizes 1000²/1080×1350/1500×2000, ≤2MB, white bg, same-margin centering, full-bleed close-up not cropped, channel choice remembered, 0 API calls.`
  - 실제로 JPG를 열어서 다음을 확인했습니다.
    - 크기
    - 2MB 이하
    - 모서리가 흰색인지
    - 가운데에서 벗어난 옷이 6% 여백으로 상하좌우 대칭 배치되는지
    - 꽉 찬 접사의 가로 전체가 남고 위아래만 흰 여백이 생기는지
  - 채널 선택이 새로고침 후에도 기억되는지, 뺀 채널 폴더가 ZIP에 없는지도 확인했습니다.
- 기존 브라우저 검사 다시 실행: browser, classify, color, compress, cuts, instagram, products(쇼피 ZIP 포함), retry, versions, modelcut 모두 PASS. 모바일 화면 가로 스크롤 없음 검사(browser)도 통과했습니다.

## ③ 아직 안 된 것·위험한 점

1. **규격이 공식 확인 값이 아닙니다.** 스마트스토어·인스타는 미확인이고, 쿠팡은 검색 요약 기준입니다. 보수적으로 만들어서 크기·용량 때문에 거절될 가능성은 낮다고 보지만, 확인한 것은 아닙니다. 실제 등록 화면에 올려 보지도 않았습니다.
2. **쿠팡 대표이미지 정책**(검색 요약): 상품만, 순백색 배경, 중앙 배치, 잘림 없음이 필요하고 콜라주와 인위적 합성은 안 됩니다. 앱은 배경·배치만 맞춥니다. 대표 사진이 이 정책에 맞는지는 사람이 확인해야 합니다. 모델컷을 대표로 써도 되는지는 카테고리마다 다르다고 나옵니다.
3. 바깥 ZIP 파일 이름은 영문(`product_channels_20261123.zip`처럼)입니다.
   - 이 작업 환경의 크롬은 한글 다운로드 이름을 ‘download’로 바꿨습니다. 사장님 PC 크롬에서도 그런지는 확인하지 못했지만, 안전하게 영문으로 했습니다.
   - ZIP 안의 폴더·파일 이름은 지시대로 `상품명_채널_순번`(한글 포함)입니다. 아주 오래된 압축 프로그램에서는 한글 이름이 깨질 수 있습니다(윈도우 기본 압축 풀기는 확인하지 못함).
4. 파일 이름의 ‘상품명’은 위쪽 상품 목록의 상품 이름입니다(예: ‘상품 1’). 상세페이지 제목이 아닙니다. 이름을 바꾸면 파일 이름도 바뀝니다.
5. 꽉 찬 접사를 1:1·4:5로 만들면 위아래(또는 좌우)에 흰 띠가 생깁니다. 자르지 않기 위한 선택입니다.
6. 실제 상품 사진으로는 결과를 보지 않았습니다(사진 도착 대기). 흰색에 가까운 옷(아이보리·흰 니트)은 옷 영역 찾기에서 배경으로 판단될 수 있습니다. 그러면 여백이 조금 달라질 수 있지만, 그때도 사진은 자르지 않습니다.
7. 업로드 자동화(스마트스토어·쿠팡 API)는 이번 범위가 아닙니다. 파일 만들기까지입니다.
