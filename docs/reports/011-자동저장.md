# 지시서 011 보고 — 완성본·상세페이지 자동 저장

작성: 2026-11-24 · 브랜치 `claude/integration-002`

이제 **드라이브에 올림 → 분류(009) → 보정(010) → 저장·상세페이지(011)**가 한 번에 이어집니다.

## ① 무엇이 되는지 (화면에서 해 볼 방법)

### 자동으로 이어 붙이기
‘자동 보정’ 칸의 **‘끝나면 완성본 저장 + 상세페이지 만들기’**(기본 켬)가 켜져 있으면, 자동 보정이 끝난 뒤 끝까지 처리된 상품마다 바로 저장합니다. 끄면 보정까지만 합니다.

### 따로 실행
상품을 고르고 **‘완성본 저장 + 상세페이지만 만들기’** → 상품 수, 만들 것, 저장 위치, 문구 자동 작성 여부, 초안이 될 상품 수가 보입니다 → **‘저장 시작’**.

### 상품마다 만드는 것
- 완성 사진(JPG 2MB 이하, 흰 배경, 상세페이지 순서)
- 상세페이지 PNG·HTML(그 상품의 테마, 새 상품 기본 ‘소프트’)
- 채널별 묶음 ZIP(스마트스토어·쿠팡·인스타 4:5·자사몰)
- 쇼피 ZIP은 보류 지시대로 만들지 않습니다.

### 문구
- **‘비어 있는 제목·설명 자동 작성 (OpenAI, 유료)’는 기본 꺼짐**입니다.
- 켜면 시작 전에 ‘문구 자동 작성: 상품 n개 × OpenAI 1회 (단가 미확인 · 토큰만 기록)’을 보여 줍니다.
- 제목·설명이 빈 상품만, 빈 칸만 채웁니다. 기존 문구 작성 지시(사진에 보이는 것과 입력된 사실만, 소재·치수·세탁법 추측 금지)를 그대로 쓰고, 비용 통계에 기록합니다.

### 확인 목록 (상품 줄마다)
- 사이즈표가 비어 있으면 상세페이지에 ‘—’로 나가고 **‘사이즈 입력 필요’**가 붙습니다.
- 제목이 비어 있으면 ‘상품 제목이 비어 있음’이 붙습니다.

### 초안
- 자동 보정에서 ‘확인 필요’ 컷이 있는 상품은 저장은 하되 상세페이지를 **`상세페이지_초안.png/html`**로 저장하고, 줄에 ‘초안’ 표시와 이유(어느 컷, 왜)가 보입니다.
- **‘확인 완료 → 정식 저장’**을 누르면 `상세페이지.png/html`로 다시 저장합니다. 드라이브에서는 같은 파일의 이름만 바뀌어 파일이 늘지 않습니다.
- 다시 자동 보정하면 확인을 다시 받습니다.

### 저장 위치
- 만든 파일은 먼저 **이 브라우저에 보관**합니다.
- 구글 드라이브가 연결돼 있으면 바로 **작업 폴더 / 상품 이름 폴더**에 올립니다(기존 규칙: 완성 사진은 ‘01 정면.jpg’ …).
- 연결돼 있지 않으면 **‘드라이브에 아직 올리지 않은 상품 n개’** 대기열에 남고, ‘구글 드라이브 저장’에서 연결하는 순간 한꺼번에 올립니다(‘지금 올리기’ 버튼도 있음).
- 보관 중인 파일은 **‘내려받기’**로 이 PC에 받을 수 있습니다.

### 바뀐 것만 올림
다시 저장해도 사진·문구·테마가 그대로면 드라이브에 다시 올리지 않습니다.

### 진행·중단
상품별 상태(대기·만드는 중·저장됨·실패), 중단·이어하기(끝난 상품은 다시 안 만듦), 한 상품이 실패해도 나머지는 계속합니다.

### 함께 고친 기존 문제 (중요)
편집 화면의 자동 저장이, 오래 걸리는 작업(자동 보정 등) 뒤에 **작업 전의 화면 상태로 상품을 덮어쓸 수 있었습니다.** 이번 검사에서 자동 보정 결과가 지워지는 것을 실제로 발견해 고쳤습니다.
- 이제 화면의 최신 상태를, 저장 안 된 편집이 있을 때만 저장합니다.
- 화면이 다루지 않는 값(상세페이지 확인 여부 등)은 지우지 않습니다.

## ② 테스트 결과

실제 구글 드라이브·OpenAI는 한 번도 부르지 않았습니다(모의 응답).

- `npm test`: **119개 모두 통과**(새로 4개, `server/autoSave.test.js`)
  - 상품별 순서, 초안 판정·파일 이름, 사이즈·확인 목록
  - 문구 자동 작성: 꺼짐이면 호출 0, 켜면 빈 상품만 1회, 다시 저장해도 다시 안 씀
  - 확인 완료 후 정식 이름, 중단·실패 처리, 자동 저장 채널(쇼피 제외)
- `npm run build`: 통과.
- 새 브라우저 검사 `tests/studio-autosave.mjs`(모의 구글 로그인·드라이브·OpenAI): **통과**
  - 드라이브 없음 → 상품 2개 브라우저 보관, 대기열 2, 내려받기 3개
  - 핑크 후드(확인 필요 컷 있음) → `_초안` 파일과 ‘사이즈 입력 필요 · 상품 제목이 비어 있음 · 확인 필요 컷: 후면’
  - 네이비 니트 → 정식 이름
  - 문구 자동 작성: 기본 꺼짐(호출 0) → 켜면 계획에 예상 표시, 빈 핑크 후드만 1회, 비용 통계 기록
  - 드라이브 연결 → 대기열 2개 상품을 올림: 상품 폴더 안에 완성 사진 JPG(2MB 이하) + 상세페이지 PNG·HTML + 채널별_묶음.zip
  - 확인 완료 → 파일 수 그대로 이름만 바뀜(다시 올린 것 2개: PNG·HTML, 사진·묶음은 그대로)
  - 같은 내용으로 다시 저장 → 올린 것 0개
- `tests/studio-auto.mjs`(010)에 **‘자동 보정 끝 → 자동으로 완성본 저장’ 확인을 추가**했고 통과했습니다(핑크 후드는 초안, 네이비 니트는 정식, 브라우저 보관).
- 기존 브라우저 검사 24개(새 autosave·auto 포함, 진짜 IOPaint로 iopaint 검사 포함)가 **모두 통과**했습니다.
  - `studio-drive`는 변경 전과 같은 곳(‘큰 PNG는 WebP로 줄여 올림’ 확인)에서 실패합니다. 검사용 사진이 작아 변환 조건에 걸리지 않는 것으로 보이며, 이번 변경과는 관계없습니다.
  - `studio-birefnet`은 BiRefNet 모델을 받을 수 없어 돌리지 않았습니다.

## ③ 아직 안 된 것·위험한 점

- **실제 구글 드라이브로는 확인하지 않았습니다**(앱 주소 OAuth 등록 대기). 모의 드라이브로 폴더·파일 이름·바뀐 것만 올리기를 확인했습니다.
- **브라우저 보관함 용량**: 상품 하나에 상세페이지 PNG·채널 ZIP 등 수 MB가 브라우저에 쌓입니다. 드라이브에 올리면 내용은 지워지지만, 드라이브를 오래 연결하지 않고 상품 수백 개를 저장하면 저장 공간이 부족할 수 있습니다(크롬은 보통 디스크 여유의 상당 부분까지 허용).
- OpenAI 단가는 여전히 미확인이라 문구 자동 작성은 예상 금액 대신 ‘상품당 1회’로만 표시합니다.
- 상세페이지 테마 글꼴(구글 글꼴)을 받지 못하면 기본 글꼴로 그려집니다(기존과 같음).
- 상세페이지 PNG를 **만들 때마다 다시 그리므로** 상품이 많으면 시간이 걸립니다(이 환경에서 상품 1개당 수 초).
- 초안 여부는 자동 보정의 ‘확인 필요’ 표시로만 판단합니다. 사장님이 직접 고친 컷도, 다시 자동 보정하거나 ‘확인 완료’를 누르기 전까지는 표시가 남습니다.

- 초안 상품은 컷을 확인한 뒤 ‘확인 완료 → 정식 저장’을 눌러 주세요.
- 문구 자동 작성은 필요할 때만 켜 주세요(기본 꺼짐, OpenAI 비용 발생).
