## ① 무엇이 되는지 (화면에서 해 볼 방법)

### 1. Photoroom 결과에도 받침대 기둥 지우기 (기본 켬, 무료)
- 원인: 받침대 지우기(`stand.js`)가 BiRefNet 경로에만 붙어 있었습니다. Photoroom도 마네킹 기둥을 옷의 일부로 남깁니다.
- 고친 것
  - Photoroom 결과에도 받침대 지우기와 누끼 뒤 정리(조각·옷걸이·꼭지)를 똑같이 적용합니다.
  - 결과가 흰 배경(불투명)으로 오면, 사진 가장자리와 이어진 흰색만 투명으로 되살린 뒤 정리합니다(`src/utils/alpha.js`). 옷 안쪽의 흰 무늬는 가장자리와 이어져 있지 않으면 그대로 둡니다.
  - ‘받침대 기둥 지우기’ 체크 칸은 이제 두 엔진 공통인 **‘누끼 뒤 정리’** 묶음에 있습니다.
- 재과금 없음: Photoroom 원본 결과를 사진에 저장해 둡니다(`rawCut`). 그래서 정리 옵션만 바꿔 다시 처리하거나, 새로고침한 뒤 다시 처리해도 Photoroom을 다시 부르지 않습니다.
- Photoroom은 원래 투명 배경(webp)으로 요청하고 있습니다. 흰 배경에서 알파를 되살리는 처리는 혹시 불투명으로 올 때를 위한 안전장치입니다. 요청 옵션은 바꾸지 않았습니다.

### 2. 1차 보정 색감 기본값: 밝기 +20 · 화사하게 +30
- 새로 넣는 사진(한 장씩·한꺼번에 올리기)에 저장되어 1차 보정에 자동 적용됩니다.

- 예전에 저장한 사진은 값이 없어 0(그대로)으로 남습니다(검사로 확인).

### 3. 자동 수평 맞추기 (새 기능, 무료, 기본 켬)
- 사진을 넣는 순간 기울기를 잽니다.
  - 근거: 마네킹 기둥·목 축(세로선), 벽돌 줄·문틀(가로·세로선), 옷 테두리처럼 곧은 선.
  - 방법: -10°~+10°를 0.1° 간격으로 돌려 보며, 세로선은 같은 x에, 가로선은 같은 y에 가장 많이 모이는 각도를 찾습니다. 세로 근거와 가로 근거를 같은 무게로 합칩니다.
  - 뚜렷한 최고점이 없으면(신뢰도 25% 미만) 돌리지 않습니다.
- 누끼 전에 원본을 바로 세운 사본으로 누끼를 땁니다. 원본 파일은 그대로 둡니다. 돌리면서 생긴 모서리는 사진 가장자리의 벽 색으로 채워서, 누끼 뒤 흰 배경이 됩니다.
- **원본 칸 아래**에서 조절합니다. 원본 미리보기는 고른 각도로 돌아가고 격자가 겹쳐 보입니다.
  - 0.1° 단위 슬라이더
  - ‘자동 수평 다시 계산’, ‘0°로’
  - 자동 계산값·신뢰도 표시
- 이미 누끼를 딴 사진은 각도를 바꾸면 바로 다시 처리합니다. 이때 Photoroom은 저장된 결과를 각도 차이만큼 돌려 쓰므로 **다시 과금하지 않습니다**.
- 전체 설정의 ‘자동 수평 맞추기’로 끌 수 있습니다. 예전 사진은 0°입니다.

- **공식 문서 확인**(docs.photoroom.com, 2026-11-23 직접 읽음)
  - 영역(마스크·상자·좌표)을 지정해 지우는 기능: **찾지 못함(미확인)**. Plus 요금제 기능 목록과 API 명세(OpenAPI 앞부분)에 그런 매개변수가 없었습니다. 지우기는 Edit With AI의 글 지시로만 가능합니다.

  - Edit With AI: 결과가 기본 1K(1024×1024)이고, 2K·4K는 Enterprise 요금제에서만 됩니다.
  - 요금: “호출당 $0.10, 옵션을 몇 개 넣어도 가격 영향 없음”, “같은 입력·같은 옵션을 두 번 보내면 2번 과금(캐시 없음)”.
  - 투명도 유지: `keepExistingAlphaChannel=auto`(기존 투명도를 누끼로 사용).
- 처리 방식

  - **얼룩**은 Edit With AI 글 지시입니다(“얼룩·먼지·보풀·실밥만 지우고 색·무늬·니트 결·봉제선·단추·모양·핏은 그대로”). **기본 꺼짐**이고, 켜면 ‘결·무늬가 바뀔 수 있고 1K로 줄어듦’을 화면에 안내합니다.
  - 켜면 다림질과 **같은 한 번의 호출**에 넣어 장당 $0.10을 넘지 않게 했습니다.
- 입력은 그 버전의 **1차 결과**(투명 누끼)이고, 원본 크기·위치를 유지합니다.
  - 같은 1차 결과·같은 설정이면 저장된 결과를 다시 씁니다(사진에 저장되어 새로고침 후에도). Photoroom은 같은 입력도 다시 과금하므로 앱에서 막습니다.
  - 결과가 흰 배경으로 오면 가장자리의 흰색만 투명으로 되살립니다.
- 비교·되돌리기: 결과는 1차 칸 바로 옆 2차 칸에 나란히 보이고, ‘이전으로’로 무료로 되돌립니다.

### 6. 실제 Photoroom 시험 (사장님 승인 · 한도 5회 중 3회 사용)

- 방법: 실제 앱(이 브랜치 빌드)을 띄워 화면에서 버튼을 눌렀습니다. 브라우저에서 유료 요청 수를 세고, 3회를 넘으면 막도록 했습니다. 같은 입력·같은 설정은 다시 보내지 않았습니다.
- 남은 Photoroom 수(`/v2/account`, 과금 없음): 시험 전 **660**/1000 → 시험 후 **645**/1000. 요금제 표시는 “basic”이었습니다.
  - 호출 1번에 **5씩** 줄었습니다. 문서의 “이미지 편집 API 1회 = 배경 지우기 API 5회분”과 맞습니다.
  - 앱 화면의 ‘남은 이미지 N/1000’은 이 단위(배경 지우기 횟수)로 표시됩니다. 이미지 편집 기준으로는 645÷5 = 약 129장 남았습니다.
- Plus 기능인 AI Ironing·Edit With AI도 오류 없이 처리됐습니다(요금제 표시가 basic이어도 거절되지 않음).

1. **받침대 기둥: 지워졌습니다.** Photoroom은 옷 아래 검은 기둥을 남겼지만, 앱의 받침대 지우기가 기둥을 지웠습니다. 마네킹 금색 꼭지와 목은 사장님 결정(기본 남김)대로 남았습니다.

3. **Ironing + 얼룩 AI: 쓰기 어렵습니다.**

   - 위의 어두운 점도 확실히 지워지지 않았습니다.
   - 실물과 달라 보일 위험이 커서 **기본 꺼짐을 유지**합니다.
4. 함께 확인된 점

## ③ 아직 안 된 것·위험한 점

1. **실제 사진으로는 확인하지 못했습니다.** 받침대 지우기(Photoroom 결과), 자동 수평, Claude 찾기 정확도 모두 합성 사진·모의 응답 기준입니다. 특히 Claude가 적극 모드에서 실제로 몇 곳을 찾는지는 사장님 테스트로만 알 수 있습니다.
2. **화사하게 +30은 채도를 30% 올립니다.** CLAUDE.md의 ‘색을 실물과 다르게 하지 않음’과 부딪힐 수 있습니다. 조명이 어두운 매장 사진을 살리는 정도라면 괜찮지만, 원래 선명한 색 옷은 실물보다 진해 보일 수 있습니다. 사진마다 끄거나 줄일 수 있습니다.
3. 자동 수평 관련
   - 벽돌 벽이 사진 전체에 고르게 있으면 잘 맞습니다.
   - 벽이 거의 없고 옷의 무늬(사선 줄무늬 등)만 강하면 무늬 방향을 따라갈 수 있습니다. 그래도 신뢰도가 낮으면 돌리지 않고, 사장님이 ‘0°로’로 되돌릴 수 있습니다.
   - 같은 크기 안에서 돌리므로, 옷이 사진 가장자리에 붙어 있으면 돌린 모서리 쪽이 조금 잘릴 수 있습니다(얼마나 잘리는지는 재 보지 않았습니다).
   - 사진을 넣을 때 기울기 계산 시간이 늘어납니다. 합성 사진(480×640)으로 한 장에 약 0.2초였고, 실제 PC 브라우저에서는 재 보지 않았습니다.
4. 각도를 바꿀 때 저장된 Photoroom 결과를 돌려 쓰므로, 처음부터 그 각도로 딴 누끼와 경계가 아주 조금 다를 수 있습니다(한 번 더 보간). 다른 각도로 새로 따려면 재과금이 필요해서 이 방식을 택했습니다.
5. **원근(앞뒤 기울기, 사다리꼴) 보정은 넣지 않았습니다.**
   - 세로선 기준으로 하려면 서로 떨어진 세로선이 최소 두 개 필요합니다. 매장 사진은 마네킹 기둥 하나뿐인 경우가 많고, 벽돌 세로 줄눈은 짧고 엇갈려서 소실점을 안정적으로 잡기 어렵습니다.
   - 잘못 펴면 옷의 위아래 폭 비율(핏)이 실물과 달라 보일 수 있습니다(CLAUDE.md 규칙).
   - 품질을 확신할 수 없어 보고만 합니다. 실제 사진에 문틀처럼 긴 세로선이 양쪽에 있는 경우가 많다면 다시 검토할 수 있습니다.
6. IOPaint로 넓은 구김을 지우면 골지 결이 흐려지고 살짝 밝게 뜹니다(위 비교의 결 보존 0.64). 상자가 구김보다 넓을수록 심합니다.
